    Saved-run reopening: plan for #335¶

    Status: Design—not shipped.

    Prepared September 19, 2026 for #335, under #330. This design record is retained alongside the source implementation. The canonical API owns shipped behavior; the verification record tracks acceptance. The remainder records the selected design and its rationale.

    The programming model owns public API contracts, the architecture owns invariants, the roadmap owns acceptance gates, and the implementation plan owns technical boundaries. Implementation depends on #331 establishing the author-UX gate. That gate is present in the working tree inspected here; this is not evidence that #331 has merged. This slice adds no requirement to #313/#319's current release scope.

    Recommended experience¶

    Add one context-managed function that returns the existing Run:

    import meta_evolve as meta

with meta.open_run("runs/example/history") as run:
    snapshot = run.summary()

print(snapshot)  # Captured while storage was open.

    The path is the directory originally passed to Storage.durable(), not its SQLite file or a parent directory containing several stores. In a shared store, pass the saved identity explicitly:

    with meta.open_run("runs/shared/history", run_id=saved_run_id) as run:
    inspection = run.inspect()

    The public callable has this proposed shape:

    open_run(
    path: str | Path,
    *,
    run_id: RunId | str | None = None,
    registry: Registry | None = None,
) -> AbstractContextManager[Run]

    Use open_run because it names both the resource lifetime and the object being opened. Reuse Storage.read_only() and Run; no new result or handle class is needed. Authors already holding storage continue to use Run(run_id, storage, registry=...) and retain responsibility for that storage.

    Keep this path-only API small. Writable mode, automatic migration, resume, directory discovery, a run catalog, and a "latest" selector are outside it.

    Selection and errors¶

    Enter the context in this order: validate arguments, open read-only storage, select one identity, validate that history, construct Run, then yield it.

    Input or store state Outcome on context entry
    Explicit RunId or valid ID string Open that identity only; do not enumerate or substitute another run.
    Explicit identity has no event stream Existing RunNotFound, even if another run exists.
    Omitted ID; no recorded runs RunNotFound with an actionable message naming the store.
    Omitted ID; exactly one recorded run Select it and validate its history.
    Omitted ID; several recorded runs New RunSelectionRequired containing the available identities.
    Missing/inaccessible directory or database Preserve DurableStoreError and its underlying cause.
    Older, unstamped, or future schema Preserve SchemaVersionRejected; perform no migration.
    Damaged schema, selected stream, or referenced artifact Preserve DurableCorruption; never fall back to another run.

    RunSelectionRequired subclasses RunError and exposes run_ids: tuple[RunId, ...]. Its message explains run_id=... and lists the available IDs in deterministic lexical order. The structured tuple makes a choice possible without parsing an exception string. Widen RunNotFound's docstring to include an existing store containing no runs; do not change its existing callers or inheritance.

    ID strings follow existing RunId validation: nonempty, without surrounding whitespace. Accept a saved run.id directly or its .value from a file. Reject other values, including a different domain ID type, with TypeError; reject malformed strings with ValueError. Do not trim, coerce arbitrary objects, or introduce a hash-format requirement. An invalid registry raises TypeError before storage opens, matching Run's current Registry requirement.

    Omitted-ID selection reads Storage.runs() once. Its lexical order is only a stable presentation order, never a creation order. If another run is committed after that listing, the selected identity remains fixed. Listing and later queries are not one long transaction. Explicit selection avoids unrelated stream replay, although the existing opener still validates the store schema.

    Validation and custom artifacts¶

    Before yielding, call the existing load_validated_run(storage, selected_id, require_existing=True). Construction of Run alone is lazy and would otherwise admit a missing or damaged history. Do not substitute a version check, best(), or a summary for authoritative loading: valid incomplete and entirely unsuccessful runs must also open.

    Entry validates the committed framework records and artifact references; it does not require a winning evaluation, verify executable component manifests, or promise that every custom artifact can be decoded. Preserve custom-value decoding at the existing query boundary:

    • registry= is passed to Run, retaining built-in codecs and adding supplied custom codecs through its current per-run index.
    • A custom history can open without its codec, and usage() remains available. A value-decoding query such as best() raises the existing actionable CapabilityError when that codec is absent.
    • A reconstructed codec registry enables decoded queries in another process; the original proposer and evaluator are unnecessary for inspection.
    • Supplied codecs remain trusted Python extensions. Reopening does not invoke their encode/decode methods on entry; queries that decode values can do so. Codec decode failures keep their existing DurableCorruption translation.

    Discard the entry validation result. Subsequent Run queries use their existing validated reads, so a live WAL writer remains observable. Each captured summary or inspection keeps its own single-frontier guarantee; the with block does not freeze all its queries to one version. The extra initial replay is the deliberate cost of rejecting invalid selections before yielding. Do not add a cache or change Run internals to avoid it in this slice.

    Ownership and read-only guarantees¶

    Implement the function with the standard-library contextmanager. Calling it creates a context manager; argument validation and I/O happen on __enter__. It opens one storage handle inside with Storage.read_only(path) as storage. That scope closes the handle after normal exit, a body exception, or an error during selection, validation, or Run construction. Exceptions propagate with their existing types and causes. Failed storage opening retains the opener's existing connection-cleanup responsibility.

    Capture summaries, inspections, usage, or selected values inside the block. These detached results remain available afterward. The yielded Run is still a live reader: later storage-dependent queries fail through the existing store error path. Add no hidden reopen, cached fallback, finalizer, Run.close(), or new closed-handle exception. A run's identity remains usable after exit.

    333 owns safe summary formatting and the I/O-free Run repr; #335 does not¶

    depend on its richer display fields to implement reopening.

    The helper grants inspection authority: no event/artifact/work commits, schema changes, migration, repair, proposer/evaluator/search execution, provider calls, or resume. A missing store directory is never created.

    The issue's "no writes" criterion needs precise acceptance wording. A planning probe against the current Storage.read_only() preserved the closed store's database and artifact hashes but created meta-evolve.sqlite-wal and meta-evolve.sqlite-shm. SQLite documents this behavior for read-only WAL databases. Define the guarantee as no mutation of committed history and no framework writes, directory creation, or migration; SQLite may maintain WAL sidecars. Document that qualification in the durability guide and #335's acceptance record before closure. Preserve live-WAL behavior; immutable=1, copying stores, and deleting sidecars are not fixes for this convenience API.

    Implementation sequence¶

    Keep this one bounded implementation PR, with three reviewable steps:

    1. Contract and opening. Add application/reopening.py containing the context manager and minimal private selection logic. Add the typed selection error in errors.py; export both public names from the root package and follow existing application exports where appropriate. Add core selection and lifetime tests with the implementation. Record the API and durability contract in canonical docs in the same change.
    2. Integrity and compatibility. Exercise real durable histories, custom codecs, failed/incomplete runs, historical fixtures, and exception cleanup. Reuse durable_loading.py, existing read-only adapters, and their error translations. No schema, event, identity, coordinator, or search changes.
    3. Complete user journey. Update the persistence lesson and its extracted download, covering save in one process and reopen in another. Add an explicit selection example for a multi-run store, preserve path discovery, and check source-generated reference coverage. Hand the verified path to #336.

    Do not add another general storage factory, selector protocol, location record, or shared validation subsystem. Existing direct construction remains supported. Keep new handwritten modules and tests below 300 lines by splitting tests into selection/integrity and lifetime responsibilities if needed.

    Focused acceptance checks¶

    Concern Required evidence
    Only-run convenience A real saved run opens without an ID; its identity and queries match direct Storage.read_only() plus Run.
    Explicit selection Typed ID and string work in one/many-run stores; missing explicit ID raises without fallback or enumeration.
    Zero/many Empty current store raises RunNotFound; several runs expose all IDs through RunSelectionRequired. Use real runs whose insertion order opposes lexical order and assert that premise.
    Arguments Wrong ID types, empty/padded strings, and invalid registry fail before acquiring storage. Creating the context manager performs no I/O.
    Lifecycle Completed, incomplete, pending-seed, and entirely unsuccessful histories open. Winner queries retain NoSuccessfulEvaluation.
    Codecs Reconstruct a custom codec registry; preserve built-ins. Missing codec permits entry/usage, fails on decoded query. Decoding faults retain existing errors.
    Integrity Missing directory/database, damaged events, missing artifacts, malformed current schema, and old/future schemas preserve typed errors and causes. No automatic repair or migration.
    Cleanup Observe connection closure on success, body exception, selection error, missing ID, corrupt stream, and failure while constructing the codec index. Body exceptions are not swallowed.
    Detached results Capture summary/inspection/usage, close storage, then use them. Explicit queries on the retained Run surface the existing store error.
    Authority Proposer/evaluator/search/provider/resume tripwires remain untouched. Verify unchanged schema, committed events, and artifact bytes; distinguish SQLite sidecars. Missing paths remain absent.
    Live reader Queries can observe a later valid committed frontier through the same handle; entry validation does not become a cache or retarget the selected ID.
    Historical read Copy retained fixtures; current-schema supported histories remain readable. An older schema is refused until a separate explicit writable migration of the copy; historical event bytes remain unchanged.
    Fresh process Save and record path/ID, remove access to original local callbacks, exit, then reopen in a separate process outside the checkout. Exercise single-run inference and explicit multi-run choice.

    Start with new tests/test_open_run.py and a lifetime test module only if needed. Use the existing custom artifact in test_run_reopening.py, state fixtures from summary/inspection tests, and retained historical fixtures. Regression coverage includes test_run_listing.py, test_run_reopening.py, test_read_only_storage.py, and the relevant durable/history tests. Existing lower-level contracts should be reused rather than duplicated exhaustively.

    Documentation integration and completion¶

    • In docs/programming-model.md, specify the new entry point, exact selection behavior, error types, codec boundary, and context lifetime. In docs/architecture.md, retain live read-only projection and authority rules.
    • In docs/implementation-plan.md, record the small application boundary. Update #335's status in the roadmap only after its acceptance evidence exists.
    • In docs/guides/durability.md, lead reopening with the convenience, then retain explicit storage ownership for advanced use. Explain WAL sidecars and preserve the separate save, reopen, resume, and exported-artifact reuse contracts.
    • In docs/learn/06-persist-run.md, replace manual only-run selection with the helper. Keep last-duration-run.txt: choosing within a known store does not locate that store after a restart. Add explicit ID selection for shared stores and capture values before closing. Keep notebook cells below 40 lines.
    • Add both exports to docs/reference/api.md's persistence/errors tier and generated member list. Update reference and persistence tests with the API; build the docs strictly and run the extracted lesson in a fresh process.

    Completion requires the focused behavior tests, unchanged supported historical reads, strict docs/reference checks, and the executable save/reopen journey. The integrated model journey and independent newcomer evidence remain in #336.

    Effort and planning evidence¶

    Estimated difficulty remains low–medium. The runtime change is a small composition of existing operations. Most work is proving error timing, resource cleanup, compatibility, and the cross-process documentation path. The estimate assumes the existing storage format, live-reader semantics, and the qualified WAL sidecar contract above; a zero-filesystem-change reader is separate scope.

These probes establish existing behavior; they are not acceptance tests for the helper; implementation evidence is recorded separately.
