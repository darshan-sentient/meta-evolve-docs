    Explicit callback context: implementation plan for #316¶

    Status: Design—not shipped.

    Prepared September 18, 2026 for #316, under #313. This specializes the proposed callback contract into binding, verification, migration, and test work. The programming model owns shipped behavior. Implementation is now recorded under the #316 source gate and verification record.

    Scope and entry gate¶

    Use #314's selected pre-1.0 release direction: one coordinated breaking release, provisionally 0.2.0, without an intermediate compatibility release or permanent legacy dispatch mode. The canonical Author API revision gate is now present alongside the separate #315 slice. The foundation decision records reviewed contracts, compatibility policy, and historical evidence. This design record does not itself complete implementation or M11 workers.

    The scope is plain decoded-value proposer callbacks passed through the ordinary execution path or registered for durable execution. Keep the evaluator, authorized context, result normalization, budgets, and coordinator unchanged. ProposerContext remains the same object with the same capabilities; this change governs how it reaches a callback.

    Findings that determine the change¶

    The inspected checkout is c04ec6b4b949b8a2702779107e25acd24feb8020 plus the local #297 documentation/docstring patch and current design documents.

    Existing behavior Implementation consequence
    _invocation_shape() tries two positional inputs before one. Replace plain-callback inference; factor=2 must keep its Python default.
    CallableProposer.__init__, .registered, and .declared share that inference. Select the binding contract by entry route; changing one helper globally would affect structural ports.
    component_proposer() prefers execute, then structural propose, then a callable. Preserve dispatch precedence and malformed-runner refusal.
    An explicit CallableProposer(dual_object) or local ComponentRef chooses the callable side first. Preserve that existing explicit-wrapper behavior; do not claim every entry route has identical precedence.
    Structural .propose(parent) is deliberately supported and tested. Preserve its parent-only convenience beside the explicit two-input structural port.
    A callable carrying .component currently uses .declared. Retain its identity checks but send its call through the plain-callback binder. Metadata must not select a different argument convention.
    Registered proposer manifests hash the function and user dependencies only. Include the actual framework binding/invocation implementation automatically.
    Resume verifies manifests before building runners or invoking their validation hooks. Retain that ordering so incompatible history cannot execute new callbacks.
    ProposerLike advertises positional callable signatures. Update the type alias to admit keyword context without adding a root export.

    1. Bind plain callbacks explicitly¶

    Use the effective inspect.signature() of the selected callable, including local bound methods and partials. Determine a call shape once per adapter construction with inert markers and Signature.bind; never call the callback body to discover its signature, and never retry after it raises TypeError.

    1. Inspect the signature. If inspection fails, raise TypeError explaining the inspectable-wrapper or explicit-structural-port alternatives.
    2. If a keyword-only parameter named context exists, bind a positional parent plus keyword context. A default on that parameter does not disable opt-in.
    3. Otherwise bind the parent alone. Reject an additional positional parameter named context, even when optional, with the keyword-only replacement. A first parent parameter named context is still a valid parent-only call.
    4. Reject any remaining unbound required inputs before seed evaluation or run commitment. Retain ordinary Python defaults for other optional parameters.
    5. Store the chosen private invocation shape and use exactly that call later.

    Required examples for the new contract:

    def propose(parent):
    return revise(parent)

def propose(parent, *, context):
    return revise(parent, observations=context.bundle)

def propose(parent, factor=2):
    return parent * factor  # factor stays 2

    These are signature sketches; revise is not a library function. No annotation, parameter count, _context alias, or variadic parameter alone requests context. f(parent, *args, **kwargs) receives just the parent; f(*args, context=...) receives the parent in args and the framework context by keyword if it binds. Positional-only parents remain valid.

    Inspect the effective signature rather than inventing a second partial-binding algorithm. For example, binding an ordinary required amount through a partial can produce a valid parent-only callable. If a partial still exposes keyword-only context, that name opts into framework delivery even if the partial supplied a default. An inspectable wrapper that hides a bound argument is the explicit alternative. Cover decorated local callables using their advertised signatures; registered decorated wrappers remain subject to the existing source refusals.

    2. Preserve the other proposer contracts¶

    Selected route Binding rule after this change
    Plain callable; registered function; bound method passed as a callback New parent-only or keyword-context rule
    Callable object with a valid configured local .component Same plain rule, preserving its exact declared component
    Object selected through .propose Existing structural two-positional-input binding, with parent-only fallback
    Non-callable local reference retaining a structural object Same structural rule
    Explicit callable adapter or local reference retaining a callable/dual object Preserve callable selection, then apply the new plain rule
    Explicit runner with .execute and valid component Existing runner contract; no callable rebinding
    PatchProposer's own callback Existing explicit (tree, context) adapter contract

    Keep .declared(ref, method) as the structural adapter path. In application/run_support.py, change the configured-callable branch to use the plain adapter with the validated local reference; its .component attribute must not turn it into a structural method. Keep component retention/role checks and validation-hook discovery intact.

    Structural binding may continue to prefer two positional inputs and fall back to the currently supported parent-only method. An uninspectable structural method has the explicit two-input port contract. Do not apply the new plain callback refusal indiscriminately to it. This is a separate port, not a legacy switch for ordinary callbacks.

    Passing object.propose as a callable and passing object as a structural proposer select different declared interfaces. Explain that distinction in advanced guidance. Preserve explicit-adapter precedence instead of taking this issue as permission to redesign component selection.

    3. Make invocation source part of verification¶

    A function can keep identical source while receiving different arguments. For example, f(parent, option=None) can take a different branch when the old adapter supplies context and the new one preserves None. Verifying only its source cannot detect this change.

    Prefer one small private module, proposed as adapters/_proposer_invocation.py, for signature selection and actual invocation. It needs no domain authority, registry, or new dependency; the adapter still owns failure normalization. This seam is justified by the separate binding contracts and the requirement to identify the framework's invocation source independently. Keep the existing adapter file below its normal size limit by moving this responsibility, not by adding a second public adapter class.

    Automatically extend registered proposer source dependencies at the existing registry manifest boundary. The dependency set must cover the private invocation module and the registered adapter's construction/dispatch wiring (for example CallableProposer.registered and CallableProposer.propose). Hash actual source, including relevant module constants; a version string or a hash of the signature checker alone is insufficient. Keep user-declared dependencies and their existing deduplication/order behavior.

    Resolve these library-owned dependencies without creating an import cycle; defer the adapter import until manifest resolution if required. Verify fresh imports in isolated processes. The same registry resolution constructs the manifest for start and resume. Evaluator manifests receive no new callback dependency, and no new persistent field, component role, or store schema is needed solely for invocation verification.

    Keep prepare_resume()'s manifest verification before runner construction, preflight hooks, broker driving, and new proposer/evaluator work. Preserve typed CapabilityError mismatches without rewriting old facts. Policy factories may still be reconstructed during manifest resolution; do not overstate this as a guarantee that no Python setup code executes.

    This intentionally changes manifests for all registered proposers using the new dependency rule, including parent-only functions. Recommend refusing old unverified invocation rather than shipping a historical execution engine in this issue. Supported history remains readable; old unfinished runs require their matching environment to continue. A component-source edit may cause an additional mismatch, which must be reported separately.

    Keep the existing run/component identity rules. Manifests are not currently part of run_id_for; the same component reference/run ID is not proof of equivalent implementations. Do not overwrite an existing run, synthesize a component version, or relabel a new run as continuation. Explain versioning and fresh-run requirements when the author deliberately changes behavior.

    4. Migrate by invocation owner¶

    A September 18 AST inventory found 52 potentially affected positional-context forms across 43 example Python files, four plain conformance helpers, and many test forms. This is a discovery list, not an exact rewrite count: structural methods and adapter-owned callbacks appear in it too. Include parameters with other names, lambdas, partials, and generated code that a name-based scan misses.

    Surface Migration and verification
    src/meta_evolve/conformance/{cohorts,context_policies,evaluators,search_programs}.py Change actual plain callback consumers; retain conformance coverage of their original laws.
    Learn/parser/SDK/feedback examples and executable reference cases Use keyword context when consumed; remove an unused second argument where parent-only is clearer; update real expected outcomes.
    Registered CLI, durable-operations, and crash-recovery examples Update source functions, versions where behavior changes, and source dependencies; record the resume consequence.
    Policy evolution, AutoResearch, and ACE Migrate inner/outer callbacks without flattening stages or changing evaluation, observation grants, retained results, or nested accounting.
    Structural SDK objects, runners, patch/history examples Trace the selected route first; keep their explicit port signatures and workspace cleanup behavior.
    Tests and historical captures Replace live old-convention tests with the new behavior; retain deliberate invalid/legacy cases and preserve old source bytes used by compatibility fixtures.
    Extracted snippets, downloads, notebooks, and live-only scripts Edit the owning source; execute supported current examples with deterministic substitutes. Preserve historical artifacts or publish a clearly versioned successor rather than silently rewriting provenance.

    Do not mechanically add * to every parameter named context. Recheck direct Python calls to each migrated function: a framework callback may also have explicit callers that now need context=. A required _context can become keyword-only context or be removed if unused; optional aliases and variadics can change behavior without any startup error and need an explicit migration note. Never turn an ordinary setting into framework context just to pass a test.

    Change ProposerLike's callable arm to Callable[..., object], retaining the structural and runner alternatives and exact runtime validation. This admits keyword-context callbacks without introducing a new root protocol or claiming that Callable[[object, object], object] describes keyword-only parameters.

    Update improve/Experiment/run/ProposerContext docstrings, the programming model, callback/SDK/experience guides, and #297's reference cases together. Show before/after forms and startup diagnostics. Do not change evaluator signatures, preset defaults, budget resolution, result fields, or root exports as incidental cleanup. #315 and #317 retain those separate concerns.

    5. Implement and verify in reviewable stages¶

    Stage Deliverable Gate before moving on
    Foundation handoff #314 decision, exact baseline, fixture provenance, release treatment Contracts/gate evidenced; historical source remains available
    Binding and dispatch Private binder/invoker, route-specific adapters, type alias, focused migrations Signature matrix passes with no double calls or unintended route changes
    Verified invocation Automatic proposer dependencies and preserved resume ordering Unchanged callback source cannot conceal changed invocation; same-runtime resume works
    Repository migration Remaining live consumers, conformance, examples, docs, generated/extracted material Original outcomes and authority/accounting rules retained under explicit equivalent callbacks
    Integration handoff Focused and required broad checks, migration/compatibility record #318/#319 can consume one identified source revision

    Treat these as review stages of #316, not independently published API releases. The production change should reach review with its migrations and source verification complete. No runtime behavior is implemented by this plan.

    Test matrix¶

    Area Required proof
    Plain signatures Parent-only, required/optional keyword context, ordinary defaults, positional-only parent, first parent named context, additional positional context refusal, variadics, missing required arguments, and uninspectable refusal
    Local Python forms Bound methods, partials including exposed context, decorated callables, callable instances, configured local identity, and misleading advertised signatures producing one normalized invocation failure
    Port selection execute precedence/refusal, .propose precedence, parent-only structural method, explicit wrapper/reference behavior, and uninspectable structural invocation
    Admission Invalid plain signatures fail before seed evaluation, proposal execution, validation-hook execution, or committed run facts through improve, run, and Session.start
    Invocation/result handling Exact context object, one signature selection per adapter, one body call, no retry after TypeError, retained usage/evidence, and unchanged escaping infrastructure/capability errors
    Manifest sensitivity Framework binder, invoker, and adapter wiring source changes affect proposer verification; user dependencies still count; evaluator manifests remain unchanged; dependency ordering and repeat resolution are stable
    Positive durability New registered parent-only/keyword-context runs resume from legal committed frontiers and match uninterrupted logical results/events; cover pushed context and admitted serial distributed execution
    Historical refusal/read Exact old source still reopens; upgraded resume refuses invocation mismatch before additional work or committed facts, without masking the case with an unrelated mismatch
    Extended behavior Existing grant, derivation, workspace/history, unknown-spend, failure, and conformance checks remain green after their plain callback fixtures migrate

    For the decisive historical case, use an unchanged module-level function whose optional second argument makes old positional delivery observable. Capture a legal incomplete run with the identified pre-cutover package and demonstrate matching-old-runtime continuation. In the upgrade check, keep evaluator and policy manifests equal so #297's policy docstring differences cannot be the actual reason for refusal. Assert the proposer mismatch specifically, and retain store/event/resource observations proving no further work occurred. Do not truncate logs or patch manifests to manufacture compatibility.

    The shared checkout now contains #314's capture scaffolding under experiments/api_revision/ and frozen components at tests/fixtures/api_v01/components.py. Its optional-argument and variadic functions fit these cases. Reuse completed captures once their package/source provenance is verified; the presence of scaffolding alone is not that evidence. Preserve those source bytes instead of migrating the historical functions.

    Start with test_callable_adapters.py, test_proposer_seam.py, registry/manifest tests, and existing resume/context/distributed suites. Add focused signature and historical-invocation test modules if their independent responsibilities would otherwise inflate existing long files. Use existing failpoint helpers for legal recovery frontiers and fresh processes for cross-version checks.

    Run focused suites first; after all live callback migrations, run the maintained runtime CI and Docs selections because the affected examples/fixtures are widely shared. Verify installed downloads and fake SDK paths without checkout imports or paid calls. Strict documentation ownership/routes and rendered signatures must agree with the implemented behavior.

    Planning evidence and completion boundary¶

    The inspected baseline passed 103 tests across callable adapters, proposer seams, registry, and manifests. Local probes reproduced the default-argument failure and keyword-context rejection, confirmed the distinct dual-object routes and parent-only structural support, and confirmed that the current registered manifest can equal the function-only digest. Probe results and the discovery inventory are under /private/tmp/meta-evolve-316-planning/.

    These checks validate findings, not the proposed implementation. Close #316 only with migrated consumers/docs, passing behavior and compatibility gates, an identified implementation revision, and explicit old-history/read/resume outcomes. #314 owns the foundation decision; #318/#319 own final integration and publication.
