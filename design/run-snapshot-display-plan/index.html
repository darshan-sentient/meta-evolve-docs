    Readable run snapshots: plan for #333¶

    Status: Design—not shipped.

    Prepared September 19, 2026 for #333, under #330. The inspected source is 1607afbb81f7c5e457f97eb437b13ffb9ad63267. This planning record is retained alongside the source implementation. The canonical API owns behavior; the verification record tracks acceptance. Release and first-run documentation work remain separate.

    The programming model owns the public contract, the architecture owns invariants, the roadmap owns acceptance gates, and the implementation plan owns technical boundaries. The author-UX gate records the follow-up scope. This is the bounded notebook/report portion of the post-M10 presentation follow-up. It adds no requirement to #313/#319's current release gate.

    Recommended public experience¶

    Keep the existing RunSummary; introduce no new result class or display API. Capture explicitly while storage is available, then display the captured value:

    with meta.Storage.durable("runs/example") as storage:
    result = meta.improve(
        seed=0,
        proposer=lambda parent: parent + 1,
        evaluator=lambda value: value,
        trials=2,
        storage=storage,
    )
    snapshot = result.summary()

print(snapshot)  # Concise text, including after storage closes.
snapshot        # Rich display when this is a notebook cell's final expression.

    Illustrative text for that completed run:

    Run <run id>
Status: Complete
Measurement: Available
score (maximize): baseline 0 → selected 2
Improvement: Improved over baseline
Proposals: 2
Evaluations: 3 (includes baseline)
Failed attempts: 0
Stop: Proposal limit reached
Task spend: $0.000000
History at capture: Saved at <absolute directory>
Recorded resume support: No (local execution)

    Saving local history does not make local callables resumable. Default in-memory execution instead says History at capture: Not saved durably. Display remains a historical snapshot; it makes no claim that the directory still exists.

    repr(result) shows only a bounded run identifier and directs readers to summary(). It never queries storage or caches a hidden summary. A fresh result.summary() after storage closes still surfaces the storage error.

    Findings that constrain the implementation¶

    Inspected behavior Decision
    application/comparisons.py already builds each summary from one validated event frontier. Extend that builder; preserve #317's consistency and comparison failure ordering.
    The summary stores decoded initial_artifact and winning_lineage values. Its generated dataclass repr can call their display methods. Supply an explicit safe repr; keep decoded fields for programmatic access but never traverse them for display.
    Baseline, failure count, persistence, and execution capability are absent from RunSummary. Capture the selected facts explicitly; formatting cannot query for them later.
    Storage declares durability but has no general location contract. Carry optional built-in location metadata; unknown custom-store locations remain unknown.
    Artifact presentation already separates inert payload records from escaped browser markup. Preserve that boundary; compact run output needs no artifact or evidence bodies.
    Core dependencies are empty; browser dependencies are optional. Use standard-library formatting and HTML escaping; no notebook/browser dependency on core import.

    The earlier #317 plan explains the existing state, accounting, and history-compatibility contracts. This issue preserves them.

    Capture the missing facts¶

    Add the following keyword-only fields to RunSummary, each defaulting to None. Existing positional fields and the three required state keywords keep their binding and meaning. None means unavailable, never zero or false.

    Proposed field Source and meaning
    primary_objective: Maximize \| Minimize \| None First objective from the captured run declaration; reuse the existing immutable type.
    baseline_score: int \| float \| None Successful primary-objective measurement of the bootstrap trial, otherwise absent.
    failure_count: int \| None Number of distinct attempts with a committed typed proposal or evaluation failure, including the baseline if it failed.
    storage_is_durable: bool \| None Capability of the handle used to capture this report.
    storage_location: str \| None Optional display path known to that handle; never recovered from a backend or the filesystem during rendering.
    capabilities: RunCapabilities \| None Existing recorded execution declaration, not a fresh resume authorization.

    For a summary built by Run.summary(), objective, failure count, durability, and capabilities are populated. Baseline and location may legitimately be absent. Old-style manual construction remains valid and displays unknown metadata honestly. Validate supplied types and finite non-boolean scores; failure counts must be nonnegative integers. Reject a supplied baseline with an unrankable summary. Do not authenticate manually assembled history or compare decoded artifact values during validation.

    Derive the baseline using projection.bootstrap.trial.id and projection.evaluation_for(...). Do not select an arbitrary evaluation by artifact digest, lineage position, or score equality: repeated content has distinct occurrences. A pending or failed seed evaluation has no baseline.

    Count the union of trial IDs whose committed TrialOutcome.failure or Evaluation.failure is present. Count a failed attempt once. Pending work, an unevaluated candidate, a rejected revision, and a low measured score are not failures merely because they did not improve the run.

    Keep usage.trials as the proposal-attempt count and evaluation_count as committed evaluations. These include failed outcomes, exclude pending work, and differ in their treatment of the seed. Preserve the separate task and experience accounting; label displayed spend as task spend, not total cost. Show a separate context/pull usage row when present, without inventing a combined cost or measured elapsed duration.

    Add private, optional, keyword-only display-path metadata to Storage, excluded from its repr and equality. Built-in durable() and read_only() capture an absolute path while opening their handle. in_memory() and compose() leave it absent. No new backend protocol, adapter introspection, public constructor option, or persisted field is needed. Snapshot construction only copies it.

    All run facts come from the same validated projection already used by _summary_inputs; handle metadata is copied from the frozen storage facade. Do not call inspect(), best(), trials(), usage(), or load a second projection to enrich a summary. This retains an event-frontier guarantee, not a new cross-store transaction guarantee.

    Keep normal dataclass equality for the added summary facts. Manually omitting facts does not make an incomplete report equal to a populated report. Update the current exact-field/equality tests deliberately; separately verify that the old constructor still binds and gives the documented unknown defaults. This is a nondurable record extension with no schema or identity change.

    Presentation rules¶

    RunSummary.__repr__ supplies a compact, safe identifier/state/score summary. __str__ supplies the readable text report; _repr_html_ supplies equivalent notebook HTML. All three use the same bounded, inert display fields. They read only captured values, never storage, codecs, component functions, clocks, environment verification, network resources, or custom artifact display hooks.

    Condition Required wording or behavior
    Complete/incomplete Complete or Incomplete, determined only by the recorded stop. Never infer that an incomplete run is currently executing.
    Rankable/unrankable Available or No successful measurement. Completion alone does not imply success.
    Baseline and selected scores present Show both, preserve zero and negatives, and identify maximize/minimize. Classify improvement with the objective's exact comparison; ties mean no improvement.
    Either score or the objective absent Report the available facts; improvement is unavailable. Do not manufacture a zero baseline or a percentage.
    Seed remains selected Report no measured improvement. Do not imply that the last proposal won.
    No stop yet Not stopped; recognized stop codes get ordinary wording, while unfamiliar codes remain visible as bounded text.
    Unknown task spend Unknown, never $0. Reuse the existing exact integer-microdollar formatter for known spend.
    Durable location absent Saved; location unspecified. A missing path is not evidence of memory-only execution.
    Durability metadata absent Unknown; do not label an old manual summary as saved or unsaved.
    Recorded resume support Identify the recorded mode and capability. Say that compatibility is not checked when support is declared; a complete run has no continuation pending.

    Use baseline → selected and the direction-aware verdict in this slice. Numeric deltas, percentages, secondary-objective panels, and target-achievement badges add no necessary information and are deferred. A failed baseline followed by a successful candidate remains rankable, with improvement unavailable.

    Keep full artifact values, evidence bodies, manifests, failure messages, and lineage lists out of compact output. The existing explicit inspection and frozen-payload artifact presentation remain their detail paths. In particular, never fall back to str, repr, _repr_html_, or equality on a decoded value. The frozen dataclass alone does not make a custom decoded value inert.

    Bound dynamic text to 200 Unicode characters per field with visible truncation and at most 16 display rows. Preserve exact values on the public record. Escape terminal control characters, and HTML-escape every dynamic value. HTML uses a small semantic label/value layout that wraps on narrow screens; no scripts, external fonts, fetched images, active links, or automatic artifact previews. Test bounds with multibyte text and very large numeric values as well as long paths and custom stop reasons; output must not depend on payload size.

    Implementation sequence¶

    Keep this as one focused issue and PR, with three reviewable slices. Do not create additional sub-issues for ordinary implementation steps.

    1. Capture and plain text. Enrich the existing summary builder, add the optional storage path metadata, and implement safe Run/summary repr and summary text. Prove closed-storage rendering, exact counting, constructor compatibility, and one-frontier capture before adding HTML.
    2. Notebook rendering. Render the same inert fields as escaped HTML and verify hooks cannot reach decoded values or optional packages. Use the existing PresentationField record in the private outer renderer meta_evolve/_run_display.py. Keep its scalar field builder alongside the markup renderer: presentation/ retains its stricter frozen-artifact-only dependency boundary. Runtime imports must remain acyclic.
    3. Documentation and review. Update the canonical contract and examples, exercise notebook desktop/narrow layouts, and record acceptance evidence against the actual integration revision before closing #333.

    Keep formatting out of application/comparisons.py, which is already near the file-size guideline. If record validation makes a split necessary, extract the run-summary record by responsibility and retain its existing import/export locations; do not reorganize the application package. Keep individual new files below 300 lines. Reuse _formatting.dollars; do not route through the CLI renderer, whose detailed output currently formats decoded artifact values.

    Verification and documentation handoff¶

    Acceptance area Focused evidence required
    Snapshot lifetime Capture while open, close, make the store unavailable, and render text/repr/HTML. Tripwires prove no later reads, codecs, or components run. Repeat for reopened read-only storage.
    Minimal Run repr Closed and unavailable stores remain representable; explicit queries still raise their real integrity/storage errors.
    Snapshot consistency Extend the existing advancement-during-capture test to the new fields. One load per summary and per comparison side, with no public-query recursion.
    Outcome semantics All four lifecycle/rankability states; pending distributed seed; failed seed then success; zero, negative, maximize, minimize, ties, and seed-selected cases.
    Counting Proposal failure, evaluation failure, failed baseline, pending/unevaluated work, unknown spend, and no double-counted failed attempt.
    Persistence/capability Memory, saved local-callable run, registered resumable run, completed run, read-only reopening, third-party durable storage without a path, and old-style manually constructed summaries.
    Safe/bounded output Hostile HTML/control strings and decoded objects with failing display/equality hooks; large artifacts, evidence, paths, and numbers; semantically equal text/HTML fields.
    Dependency boundary Core-only import and text/HTML generation without notebook or browser extras. New safety tests must not sit behind pytest.importorskip("starlette").
    Historical behavior Reuse historical read fixtures without rewriting bytes. Preserve strict comparison and winner queries; test same-runtime continuation separately from expected source-drift refusal.
    Visual review Actual notebook display at desktop and approximately 360px width; long labels wrap, states remain legible without color, HTML and plain-text fallback convey the same facts.

    Low–medium complexity; estimated two to four focused working days, excluding the #331 dependency, review queues, and publication. The main risk is truthful capture and compatibility, rather than HTML styling. No coordinator, storage schema, search, budget, or provider overhaul is needed.
