    M10 local-author design¶

    Status: Design—not shipped.

    This page is the subordinate design record for #151 (M10.0). The milestone roadmap owns status, order, gates, and exclusions. The implementation plan owns technical staging. Journey 2's Experiment declaration and dual-form run() call are shipped by M10.1, Journey 1's improve() call is shipped by M10.2, Journey 3's functional search is shipped by M10.3, and the aggregate Run.inspect() read model is shipped by M10.4. Journey 4's Session is shipped by M10.6. The read-only local browser shipped in M10.7; frozen-payload artifact presentation, previews, diffs, and canonical attachments shipped in M10.8. At the time of this record the parent M10 remained open. Its current status is owned by the milestone roadmap.

    The live examples were later reorganized by user journey under examples/learn/, domains/, operations/, agents/, and research/. Numbered paths below are frozen historical measurement evidence; the live functional-search fixtures now reside at examples/learn/functional_search/, and the live future reservation is examples/research/trusted_workers/.

    The public story is: proposers create candidates, evaluators judge them, search decides what to try next, and Meta-Evolve records the entire process.

    Vocabulary tiers¶

    The beginner tier names the seed, proposer, evaluator, and bounded trials=. The declarative tier adds Task, Experiment, search, context, experience, random seed, and registry. Storage, execution mode, and a narrowing budget are execution overlays. The extension tier retains SearchProgram.next() and the kernel records needed by advanced policy authors.

    trials= is an author-facing cost and control limit, not exposure of kernel Trial records. Search state, trial specifications, operators, work items, events, and raw randomness stay off the simple path.

    Measurement rules¶

    A physical line is every nonblank, non-comment code line. Imports and lines containing only delimiters count. Every counted line is classified once: algorithm expresses the limit, selection, stopping, or domain declaration; scaffolding adapts protocols, identities, execution, or syntax around those choices. Proposer, evaluator, and artifact-domain logic is held outside every search slice.

    The shipped before-side for functional search is this runnable full-protocol shape, reduced from the repository's custom-search test without changing its protocol work:

    from meta_evolve import domain
class IncumbentRefinement:
    policy = domain.PolicyRef("example:incumbent", "1", origin="local")
    def __init__(self, proposer):
        self.proposer = domain.ComponentRef.local_proposer(proposer)
    def next(self, state):
        if state.usage.trials >= 20:
            return domain.Stop(reason="trial limit reached")
        parent = state.incumbent_id or state.start.seed_artifact_id
        return domain.TrialSpec(
            task_id=state.start.task_id,
            parent_ids=(parent,),
            proposer=self.proposer,
            operator=domain.OperatorSpec(kind="rewrite"),
            budget=domain.Budget(trials=1, evaluations=1),
            random_seed=state.randomness.seed("trial"),
        )
search = IncumbentRefinement(propose)

    It has 18 total lines: 3 algorithm and 15 scaffolding. It has one kernel import and constructs a trial manually. Changing only the name and limit for the two composition fixtures leaves those counts unchanged.

    Journey 1: beginner improve()¶

    The smallest shipped declaration is bounded and can choose durable storage without claiming durable-local reconstruction:

    run = meta.improve(
    seed=(),
    proposer=complete_one,
    evaluator=len,
    trials=3,
    storage=storage,
)

    Journey 2: explicit expansion¶

    The shipped beginner call lowers exactly to this declaration and execution:

    experiment = meta.Experiment(
    task=meta.Task(evaluator=len),
    seed=(),
    proposer=complete_one,
    search=meta.Greedy(max_trials=3),
)
run = meta.run(experiment, storage=storage)

    Journey 3: functional incumbent refinement¶

    The shipped author-owned equivalent of the full-protocol before-side is:

    @meta.search(max_trials=20)
def incumbent_refinement(search):
    return search.expand(search.incumbent or search.seed)

    The callback sees opaque occurrence-preserving seed and incumbent handles, immutable declared configuration, expand(), and stop(). The adapter owns budgets, proposer and operator binding, replayed stopping, and named randomness.

    Journey 4: uninterrupted, paced, and resumed Session¶

    Uninterrupted execution remains one call:

    run = meta.run(experiment, storage=storage)

    Paced execution completes one committed decision per step:

    with meta.Session.start(
    experiment,
    storage=storage,
    budget=budget,
    mode="local",
) as session:
    for decision in session:
        observe(decision)
run = session.run

    Recovery continues the same authority and budget rather than accepting a new decision:

    with meta.Session.resume(
    run_id,
    storage=storage,
    registry=registry,
) as session:
    for decision in session:
        observe(decision)
run = session.run

    Uninterrupted and resumed execution must produce byte-identical durable histories. Human choices require a future declared component with recorded inputs; Session.step(decision=...) is prohibited.

    Journey 5: deterministic textual-feedback descent¶

    This shipped functional-search fixture is derived from the deterministic development loop in examples/20_harness_evolution/; its proposer, evaluator, artifact domain, and held-out promotion check remain outside the slice:

    @meta.search(max_trials=2)
def textual_feedback_descent(search):
    """Expand the incumbent after deterministic development feedback."""
    return search.expand(search.incumbent or search.seed)

    It is a deterministic, local, unpaid, unnumbered fixture under examples/functional_search/, not a new numbered example.

    Journey 6: deterministic AutoResearch composition¶

    This shipped outer-search fixture is derived from examples/19_autoresearch/; private selection, public evidence, inner runs, and held-out evaluation remain evaluator- or user-owned:

    @meta.search(max_trials=2)
def autoresearch_recipe(search):
    """Expand the selected recipe for the next bounded outer evaluation."""
    return search.expand(search.incumbent or search.seed)

    It is also deterministic, local, unpaid, unnumbered under examples/functional_search/, and outside the numbered sequence. Neither fixture creates or consumes the reserved examples/22_trusted_workers/.

    Friction scorecard¶

    This is the historical M10.0 measurement, so its original proposed slice labels and line counts remain unchanged as later journeys ship.

    Public names count distinct public API names in the slice; kernel imports count import statements from internal extension namespaces. A durability rewrite is an author change required to move from local execution to durable-local reconstruction. Reduction is the drop in scaffolding from the 15-line shipped functional-search baseline; it is published only where that comparison applies. The now-runnable Journey 5 and Journey 6 fixtures are statically recounted by the same rules at 3 algorithm lines and 1 scaffolding line each.     Decisions¶

    • SearchProgram.next() remains the full 1.x extension protocol. Renaming it to decide() adds churn while @meta.search removes routine exposure.
    • Decorator configuration is immutable, serializable, and identity-visible. Hidden closure configuration is rejected. Lowering is exact and introduces no coordinator branch or special case.
    • Outer and inner loops, generations, and episodes remain relative explanatory terms, not new core types.
    • Dictionary-returning CLI factories remain supported through 1.x and now emit the M10.1 DeprecationWarning beside the typed alternative; removal is no earlier than 2.0.
    • M10.3 #164 shipped the docstring-derived DecisionDescription contract.

    Deferred and rejected alternatives¶

    After M10, class-based harness surfaces may remove repeated field names and named search/context presets may improve discovery only when they lower exactly through existing validation, identity, authority, and durability contracts. Reflective proposer recipes remain user-owned.

    Rejected alternatives are ambient configuration, execution-owning forward(), optimizer-owned compile(), hidden captured configuration, injected human decisions, fused proposer/evaluator/search layers, and any sugar that requires a coordinator, kernel, artifact, provider, or infrastructure special case.
