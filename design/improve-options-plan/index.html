    One objective and explicit context: plan for #334¶

    Status: Design—not shipped. This retained design record is subordinate to the canonical shipped contract. Source implementation and checks are recorded in the verification record; package publication is separate.

    Prepared September 19, 2026 for #334, under #330. This selects a small extension to improve(); the selected contract is implemented. The programming model owns the shipped API and the architecture owns its execution invariants.

    Outcome and entry gate¶

    A caller can minimize an error, set a satisfaction target, or supply bounded feedback without first constructing a Task and Experiment. The expanded declaration remains the reusable form of the same execution.

    Implementation follows #331's author UX gate and uses #332's feedback contract. The accessor spelling, disabled-context behavior, and recency policy are covered by the dependency's tests and this slice's integration checks. Source integration does not close the GitHub issues or establish package publication.

    Treat this as an additive API change in a subsequent release, outside the retained #313/#319 0.2 scope. The release owner assigns the version; this issue does not bump it, publish a package, or rewrite the frozen release contract. The selected boundary is recorded in the canonical implementation plan. Contract updates, executable examples, and tests accompany the behavior.

    Selected public contract¶

    Append two keyword-only parameters, preserving the existing parameter order, defaults, exports, and concrete Run return annotation:

    def improve(
    *,
    seed,
    proposer,
    evaluator,
    trials: int = 20,
    storage=None,
    random_seed: int = 0,
    objective: Maximize | Minimize | None = None,
    context: ContextPolicy | None = None,
) -> Run:

    Use existing objective classes and the existing context policy protocol; no new root export or declaration type is needed.

    • objective=None inherits Task's default: maximize score, with no satisfaction target. A supplied Maximize or Minimize becomes the task's one-element objectives tuple. Strings, booleans, and sequences are invalid; a tuple containing one objective is not another accepted spelling.
    • context=None preserves disabled pushed feedback. Pass a supplied policy directly to Experiment.context. NoMemory() retains its existing equivalence to None. Structural local policies remain supported through existing validation; do not restrict this keyword to built-in classes.
    • trials still bounds successor proposals, including failed proposals. It must be a finite nonnegative integer; None and booleans remain invalid. Zero evaluates only the seed. Storage and random-seed behavior stay intact.

    The call reads:

    result = meta.improve(
    seed=seed, proposer=propose, evaluator=evaluate, trials=20,
    objective=meta.Minimize("error", satisfy=0),
    context=meta.RecentAncestors(),
)

    RecentAncestors is the policy supplied by #332. The proposer requests feedback with def propose(parent, *, context) and reads context.evidence.latest("failed-cases"). That argument is an evidence label, not the objective's metric name. Keep the distinction explicit in the example.

    Stop rule for facade expansion¶

    Only consider individual declarative values with an obvious default and an existing canonical owner. This criterion is necessary, not automatic permission to add another keyword: every addition needs a named requirement and gate.

    This slice admits exactly objective and context. Multiple objectives, artifact/environment declarations, budgets, custom search, registry, execution mode, and pulled experience use Task / Experiment / run. In particular, do not add budget until another decision settles its interaction with trials. Do not introduce **options, a procedure object, or provider options.

    Lowering and behavior¶

    Keep the production change in application/improvement.py:

    1. Preserve the existing trials=None rejection.
    2. If objective is None, construct Task(evaluator=evaluator) exactly as today. Otherwise construct Task(evaluator=evaluator, objectives=(objective,)). Use an explicit is None check so false values cannot silently become defaults.
    3. Construct Greedy(max_trials=trials) and the existing Experiment, adding only context=context; preserve random_seed forwarding.
    4. Call the existing local run(experiment, storage=storage).

    Do not duplicate Task objective validation, normalize policies in the facade, call select() early, or create an execution branch. The wrapper contributes no durable identity, schema, event, policy, or accounting logic.

    Input or situation Required behavior from the existing engine
    Finite scalar evaluation Becomes the sole objective's measurement, including a custom name such as error.
    Mapping or rich evaluation Must contain the declared metric; extra diagnostic measurements are retained. No implicit renaming from score to error.
    Missing or invalid measurement Recorded typed evaluation failure, never a fabricated low score or preflight declaration error. All failures can produce a Run with no winner.
    satisfy=None No new target. A successful seed does not itself cause early satisfaction.
    Seed already satisfies One evaluation, zero proposals, objective_satisfied, including when trials=0.
    Unsatisfied seed, trials=0 One evaluation, zero proposals, trial_limit_reached.
    Ties or regressions Keep the earlier best result; preserve every committed attempt and its lineage.
    Declared context Select the same bounded records as the expanded path. Do not enable pulled experience or expose rejected siblings beyond the policy.
    Disabled context Valid when feedback is unused. Under #332's selected contract, attempting latest() raises ContextDisabled; do not catch it in the facade.
    Declared policy with no match latest() returns None; bounded selection and truncation do not trigger a hidden history query.

    Preflight rejects malformed objective/context declarations before evaluation, proposal execution, or committed run facts. This is not a promise to execute arbitrary policy code ahead of time: selector errors happen at selection, and disabled-access errors happen when the proposer requests evidence. Preserve those distinctions and the expanded path's exception types.

    Compatibility and proof boundary¶

    For the same callbacks, declarations, random seed, implementation revision, and isolated starting storage, the simple and expanded forms must agree on:

    • run ID and exact serialized events, including selected context;
    • artifact occurrences, decisions, selected measurements and winning lineage;
    • proposal/evaluation counts, reported resources, unknown spend, failures, lifecycle, and stop reason.

    Compare declared context to the same declared context. Enabling feedback or changing the objective can legitimately change identity and behavior. Equivalence does not promise identical external model outputs across separate executions.

    Keep handle metadata separate from run facts: #333's summary captures the storage location and durability. Two stores with different paths need not produce equal complete summaries. Assert each location independently and compare the shared summary facts; never normalize event bytes to obtain equality.

    Capture default-call equivalence after #332's handoff, then compare before and after #334. Do not mistake #332's source-manifest changes for facade regressions. This wrapper is not currently an automatic registered-proposer dependency; verify that remains true and keep error/accessor implementation changes out of this slice. Historical reading and exact-source resume remain separate checks. Do not weaken source verification, introduce a schema migration, or claim that persisted local improve() runs become resumable. Registered durable execution still uses the expanded path.

    Focused validation matrix¶

    Extend the signature/default assertions and baseline equivalence in tests/test_improve.py. Put the additional behavior cases in tests/test_improve_options.py, with feedback integration in tests/test_improve_context.py, so each file remains small. Reuse existing projection/serialization helpers where they already express the assertion; avoid a generic scenario framework.

    Documentation and example changes¶

    • Update improve's docstring and the canonical programming model: signature/defaults, expansion stop rule, scalar metric naming, explicit feedback, and persistence wording. The generated API reference should consume that signature rather than acquire another handwritten copy.
    • Update the evaluation guide to show the single objective on the short path; retain the expanded example for ordered multiple objectives. The Task ordering contract does not change.
    • After #332 lands, update the feedback lesson with a short equivalent improve(context=...) declaration and the accepted accessor. Retain its expanded explanation and the disabled/empty/truncated distinctions.
    • Add small executable reference cases to examples/learn/reference_cases.py and API examples, covering scalar minimization and feedback. Extend tests/test_api_reference_examples.py to execute them. Keep files below the size guideline; split by example responsibility if needed.
    • Record the additive release treatment and revised compatibility guidance. The credential-free quickstart remains valid unchanged. #336 owns the full practical journey and newcomer study; neither is required to invent another SDK integration in this issue.

    Delivery sequence and difficulty¶

    One focused implementation PR after the dependency handoff should suffice:

    1. Confirm #331/#332 acceptance and record the canonical technical boundary; capture the default baseline and retain #333's summary comparison distinction.
    2. Add the two parameters and direct lowering, with signature, failure-timing, default-preservation, and behavioral equivalence tests.
    3. Update executable examples, canonical contracts, and release guidance in the same PR; run focused checks and the required integration gates.

    Difficulty is low–medium. The production change is a few lines of existing declaration composition. Most work is in deterministic equivalence coverage and consistent teaching. #332's finalized behavior and #333's summary equality are the integration risks; neither calls for a coordinator overhaul.

    Planning observations¶

    Inspected committed baseline: 1607afbb81f7c5e457f97eb437b13ffb9ad63267, with concurrent #331–#333 and release edits left intact. Initial planning made no runtime changes; the subsequent implementation is recorded separately above.

    The first improve/experiment baseline run produced 33 passed, 1 failed: the durable equivalence assertion compared complete summaries from different directories, including #333's new storage_location. A concurrent update to that test excluded this handle field; the repeat run passed all 34 tests. Preserve that distinction when extending the assertions for #334.

    A disposable forwarding prototype outside the repository passed 22 paired runs across memory/durable storage, 2 comparisons with the current facade, and 7 malformed-declaration checks without evaluations or committed facts. It exercised scalar/mapping objectives, satisfaction including seed-only cases, missing metrics, disabled/empty/recent feedback, and reported resources. These observations used #332's local implementation and excluded handle metadata from summary equivalence; they demonstrate feasibility, not completed acceptance or a shipped API. Formal tests must repeat them against the accepted dependency.
