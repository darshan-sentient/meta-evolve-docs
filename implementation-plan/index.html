    Implementation Plan¶

    This document is the technical companion to the canonical milestone roadmap. The roadmap owns implementation order, demonstrations, and acceptance gates. The programming model owns public API signatures. This plan records only the package boundaries, ports, adapters, and technical choices needed to implement each milestone.

    Pre-milestone API spike¶

    Status: Shipped. The spike lives under experiments/00_api_spike/ and ran both required demonstrations; its ergonomic findings are recorded in real_model_findings.md and reflected in the programming model. The section below is kept as the record of what the spike was scoped to prove.

    Before creating the durable package, build a disposable one-to-three-file prototype under experiments/00_api_spike/.

    It must run the same target API against:

    1. deterministic integer improvement with greedy and best-of-N search;
    2. a real-model prompt-optimization example with a small callable proposer and evaluator.

    The spike may use closures, live objects, and an in-memory list. It does not need events, ports, grants, persistence, or production provider handling. Its purpose is to test whether Task, meta.run, Proposer, Evaluator, SearchProgram, and Run feel coherent in working code.

    Treat the implementation as disposable. Feed ergonomic findings back into the programming model, then implement only the justified contracts in Milestone 1.

    Milestone 1: deterministic in-memory kernel¶

    Status: Shipped (July 21, 2026). The exit gate is covered by the canonical number-search example and the retained-event reconstruction acceptance suite. This is event-to-projection replay and built-in decision reproduction, not process restart or resume.

    Domain records¶

    Implement frozen, serializable models for only the first complete logical loop:

    • Task
    • Artifact
    • Proposal
    • TrialSpec, Trial, and TrialOutcome
    • Evaluation and Evidence
    • SearchDecision, PolicyRef, and OperatorSpec
    • Budget and Usage
    • the minimal typed events and projected SearchState

    Trial is the logical experiment. WorkItem is its delivery envelope and stays an internal kernel record: the sequential local coordinator may introduce it when scheduling needs a seam, and it never appears in user-facing types. Do not add leases or retry-attempt identities until distribution requires them.

    Use opaque typed identifiers and schema versions on durable envelopes. Keep semantic artifact kind separate from storage representation. Simple integers or strings are normalized through a basic artifact codec rather than special-cased by the coordinator.

    Durable foreign references use explicit _id and _ids suffixes. The common artifact envelope exposes kind, representation, schema_version, and parent_ids; Task.artifact_kind names the same semantic classification as Artifact.kind.

    Start with callable proposer and evaluator adapters plus in-memory stores. Do not introduce ExperienceGraph, SDK runtime, workspace, sandbox, or SQLite ports in this milestone.

    M1.1 deliberately made Artifact responsible for freezing payloads, validating content digests, and carrying occurrence identity. Storage adapters therefore accept complete, already validated artifacts and preserve them as-is instead of reconstructing artifacts from separate payload and metadata arguments.

    M1.3 keeps replay as a pure events → SearchState fold. Durable event facts record the run configuration, policy decisions, completed trials, artifact occurrences, and evaluations; the disposable state derives best-so-far, failures, usage, remaining budgets, and decision-scoped randomness through plain properties. Historical budget overages remain replayable and floor projected remaining resources at zero, while Budget.remaining_after retains its strict rejection semantics for prospective accounting. Unknown billed spend also floors a bounded monetary remainder to zero and blocks further admission; it does not convert a valid completed result into an overage failure. Omitted spend fields still decode as zero; explicit null retains unknown usage. Named seeds and logical decision ids use versioned SHA-256 derivation rather than Python's process-randomized hash.

    The M1.3 SearchProgram contract intentionally contains only next(state). Archive composition remains Milestone 2 work. Proposal submission facts, in-flight trial transitions, authority checks, and idempotent completion remain with the callable-adapter and coordinator slices that can establish their full semantics.

    M1.4 adds the independently testable callable boundary. Proposer and Evaluator ports operate on decoded Python values, and local callable adapters normalize plain or rich returns into immutable ProposalResult and EvaluationResult records. EvidenceDraft carries validated evidence content before the coordinator assigns identity. Evaluator normalization validates finite metrics, non-negative uncertainty, and coverage of the task objectives; additional diagnostic metrics remain valid, while objective direction stays in the task. Callable-reported tokens, charged monetary spend, and wall time remain attributable to the action, but nonzero trial or evaluation counts are invalid because the coordinator owns those counts. When a returned failure is converted to InvalidOutput — a role-mismatched failure kind or a count violation — the original failure's kind, message, and details are preserved in the invalid output's details. These boundary records are not durable types and do not expand the root public API or serialization allowlist.

    M1.5 implements the sequential coordinator and durable conversion. One rich lifecycle projection is the replay validator and derives the smaller policy-facing SearchState. The coordinator commits a causal bootstrap trial without charging a successor attempt, commits successor proposals and artifacts before evaluation, mints evidence identity, preserves lineage across evaluator failure, and accounts for authoritative proposal attempts and evaluator calls.

    M1.6 records one durable SearchSpec on RunStarted: the policy reference, frozen declared configuration, and authorized proposer. Internal prepare_search() composes that declaration with the executable program and a deterministic identity key. Presets bind themselves structurally; Greedy.bind owns its mutate operator and unit trial allocation, while already executable custom programs pass through unchanged. This keeps preset-specific binding and identity formatting out of run() and lets retained events reproduce built-in Greedy decisions without adding replay to the root API.

    Sequential coordinator¶

    while True:
    state = projections.search_state(run_id)
    decision = search.next(state)

    if isinstance(decision, Stop):
        coordinator.stop(decision)
        break

    coordinator.execute(decision)

    For a TrialSpec, the coordinator:

    1. validates authority and remaining budget;
    2. derives and records named deterministic random substreams;
    3. commits the stable Trial identity with the decision;
    4. allocates a local WorkItem;
    5. invokes the proposer and commits its proposal before evaluation;
    6. captures the successor artifact occurrence;
    7. commits the execution TrialOutcome and usage;
    8. invokes the evaluator outside candidate authority and records its separate evaluation and evidence.

    The seed follows the same causal record chain through a coordinator-owned bootstrap trial at logical step zero. It consumes one evaluation but zero successor trials, so policy logical step one and Greedy.max_trials begin with the first proposer attempt. Projected counts sum the authoritative usage on outcomes and evaluations rather than counting record collections.

    Operator policies return typed OperatorSpec values. User-facing string shorthands are normalized before the trial is committed.

    Reference problem and exit¶

    Use integer search. The same task, initial artifact, root random seed, policy, and budget must produce the same decisions and projected state. Rebuilding a fresh in-memory projection from the retained event list must reproduce the result; process restart and filesystem persistence remain Milestone 4 concerns.

    The kernel exits this milestone when trial identity, lineage, budgets, failure taxonomy, deterministic randomness, duplicate completion, replay, and policy replacement have focused tests.

    Milestone 2: replaceable search policies¶

    M2.1 establishes the shared durable boundary before adding another preset. ArchiveUpdate is a record-only SearchDecision: projection validates its evaluation, candidate, admission or rejection, optional eviction, and complete rank-ordered membership. PolicyDecisionExplained immediately links rationale to a decision without changing the frozen M1 decision or trial schemas.

    The runtime commits trials, archive updates, and stops through one application path. Policies may optionally describe a decision and name the random streams they used; the runtime derives the recorded seeds. Deterministic fallbacks keep a custom policy's required contract at next(state) only. The initial shared conformance harness covers Greedy and such a minimal custom policy. Ranking, tournament selection, and composed archive or stopping policies wait for a second concrete use in BestOfN or Population.

    M2.2 adds BestOfN(max_trials=20) through the same preset-binding and SearchProgram.next(state) contracts as Greedy. It always expands the seed, uses the derived stable top-1 result view, emits no ArchiveUpdate, and binds a mutate operator with a one-trial, one-evaluation allocation narrowed by remaining budget. Its versioned declaration is best-of-n@1 with frozen max_trials configuration. The bootstrap evaluation participates in ranking but consumes neither a successor trial nor a policy step.

    Keep this small implementation parallel to Greedy in M2.2. M2.3 is the extraction checkpoint: Population supplies the third concrete policy shape needed to judge whether shared selection, allocation, stopping, ranking, or archive seams simplify the code. Put Greedy, BestOfN, Population, and a minimal custom policy behind one conformance suite without adding coordinator cases.

    M2.3 adds Population(size=3, tournament_size=2, max_trials=20) through the same preset contracts. The extraction checkpoint yielded exactly one shared seam: the private stable-ranking primitive rank_evaluations in the domain, which now backs the incumbent view, the derived result view, and population membership. Selection, allocation, and stopping seams stay inlined; three policies did not justify them. Population processes every evaluation through one record-only ArchiveUpdate before any stop, and draws tournament members from the named selection stream with a self-contained integer draw rather than random.Random, whose sampling algorithm may change across Python versions and would break historical decision reproduction. When no member is admitted it stops with population_empty rather than expanding a non-member seed.

    M2.4 completes the milestone with frozen, slotted RunSummary and RunComparison application views. Run.summary() retains only immutable identities, declarations, usage, content references, and frozen payload values; it carries no storage or run-token dependency. Run.compare() rejects every task, primary-objective, budget, initial-artifact, evaluator, and proposer declaration mismatch independently. Policy declarations/configurations and root seeds may differ, and exact primary scores tie without secondary tiebreaking. The views remain outside the durable serialization allowlist.

    examples/learn/policy_comparison/ owns the deterministic 40-seed benchmark and aggregation. A tiny main.py executes it under its canonical local callable identity, while an executed notebook presents the full score, evaluation, and usage distributions plus representative topology. Notebook verification uses locked nbconvert tooling and always writes execution output to a temporary file. The companion executed milestone_2_tour.ipynb is the guided entry point for the completed milestone and keeps internal projection inspection explicitly separate from the simple callable path.

    The coordinator must not know which policy is active. Selector, Allocator, OperatorPolicy, ArchivePolicy, and StopPolicy may begin as small protocols or values only when at least two implementations justify each seam.

    Record each decision's policy version, logical identity, observed state reference, named random substreams, and rationale metadata. Comparisons use equal declared evaluation budgets and deterministic tie-breaking.

    M3.1 is the read-only temporal projection only. It adds durable ExperienceRef(run_id, kind, occurrence_id) values based on existing occurrence identities and immutable ExperienceRecord, trial-centered ExperienceNode, ExperienceQuery(task_id, run_id, as_of), and ExperienceState views. replay_experience_graph() first uses the validated run replay path, then attaches the exact committed decision, explanation, proposal, artifact-creation, outcome, evidence, evaluation, and completed-trial records. It does not change coordinator, event-store, artifact-store, existing identity, or event-byte contracts. The #98 conformance closure later root-exported those four values plus ExperienceGraph as the minimal type-complete, read-only surface needed to implement a third-party ContextPolicy; replay construction stays in meta_evolve.application.

    Parent edges follow declared parent artifact occurrences to their producing trials. Relations preserve parent order and deduplicate; returned nodes sort by (logical_step, trial_id). Ancestors exclude self, siblings include self, frontier returns visible causal leaves rather than archive members, and a trace covers the target trial plus its accessible ancestors, with records sorted by event sequence plus a fixed kind order. Historical as_of boundaries are inclusive, including bootstrap step zero.

    One private access predicate enforces matching task and run, inclusive logical time, local occurrence, visibility, and synthetic retraction. All inaccessible direct targets raise the same content-free ExperienceAccessDenied; collection queries omit inaccessible nodes and do not cross them. The hidden, retracted, and non-local sets exist only to test the filtering contract. They are not a public policy abstraction and establish no Milestone 12 governance contract.

    M3.2 implements NoMemory, AncestorsOnly, and BestSibling with direct max_records=20 and max_chars=8_000 defaults. None and NoMemory() add no declaration, wrapper, identity input, fact, or trial policy. A non-default ContextSpec is the next run-identity input after the M1/M2 segments and is declared after bootstrap. A generic search wrapper stamps its PolicyRef into successor TrialSpec values; a separate generic coordinator operation selects or reloads the exact bundle. No coordinator branch depends on a policy or graph relation.

    Without pull access, selection follows PolicyDecisionMade → PolicyDecisionExplained → ContextSelected → ProposalSubmitted; with pull access, grant issuance and audited operations sit between selection and proposal. Replay validates declaration authority, ordering, uniqueness, observed version, strictly prior visible references, and exact source values, then returns the committed bundle without invoking the selector or renderer. Context record/render usage remains separate from task Usage.

    M3.3 adds run-level PullAccess, durable ExperienceSpec and per-successor ExperienceGrant, scoped pull operations, exact observations/comparisons, and cumulative ExperienceUsage. The serialized access spec follows any ContextSpec in run identity. None contributes no identity segment, event, grant, reader, or compatibility change.

    The local grant fixes task, run, trial, and as_of=logical_step - 1, then enforces operation, result, record, and independently rendered-character bounds. Each structurally valid call commits an attempt before validation and then exactly one success, denial, or exhaustion. Attempt 21 under the default 20-operation limit is charged as operation 21 and audited as exhausted. Successes store the exact returned value; replay holds each success to the shared deterministic contract against committed sources and returns the committed value without re-running live retrieval, traversal, or rendering logic. The reader holds only its grant, a view of its own committed operations, a grant-scoped graph built once per grant, and a trial-bound append capability for the permitted audit facts. Identity and visibility remain single-user stubs. Principal authorization, licensing, and federation policy are deliberately deferred; future-information leakage and observation recording are not.

    Evaluate push-only context, pull-only exploration, combined access, and no-memory baselines under equal budgets.

    M3.4 adds no new lifecycle event. Durable and callable proposals gain an ordered derived_from tuple whose empty default is canonically omitted. A small application contract reconstructs the trial observation ledger from committed context selections and successful pull results, then serves both live completion and proposal replay. The coordinator applies resource exhaustion, derivation policy, and reported proposer failure in that order.

    RunExperienceUsage is a derived application view. It sums committed bundle usage and the final cumulative pull ledger once per grant. RunSummary carries both memory declarations and this projection; RunComparison allows different memory declarations and reports exact equality flags. The canonical examples/learn/experience_reuse/ experiment closes the milestone with all four memory variants under identical non-memory declarations and budgets.

    Milestone 4: durable local kernel¶

    Status: Shipped (July 24, 2026; #4, #47). The implementation uses filesystem content-addressed artifacts, an append-only SQLite event stream, explicit component manifests, atomic storage composition, and shared replay/resume validation.

    SQLite object and transition store¶

    Store immutable domain objects as normalized append-only records or content-addressed envelopes. Store lifecycle changes in an append-only event ledger. Creation of an object and its corresponding transition event occurs in one transaction.

    Add:

    • optimistic event-stream concurrency;
    • durable run, trial, work-item, usage, population, and experience projections;
    • stable idempotency keys and logical steps;
    • exact context bundles and experience-query results;
    • as-of search-state reconstruction;
    • explicit schema versions and migrations.

    Object records are authoritative for object content. Events are authoritative for the fact that transitions occurred. Projections are disposable and rebuildable.

    Filesystem artifact store¶

    .meta-evolve/
├── artifacts/sha256/...
├── runs/...
└── meta-evolve.sqlite

    Identical payload bytes reuse content identity while distinct artifact occurrences retain trial, proposal, contributor, and parent lineage.

    Recovery scenario¶

    Terminate a deterministic run at each important transition, reconstruct a new coordinator from disk, resume from committed state, and compare it with an uninterrupted run. Closures are rejected in durable-local mode or cause an explicit capability error before execution; they never silently create a run advertised as resumable.

    Milestone 5: executable artifacts¶

    Status: Shipped. Milestone 5 is complete through the M5.4 canonical clamp acceptance. The closure adds integrated assertions, an executed tour, and documentation only; it adds no production port, schema, registry, patch format, or authority claim.

    M5.1 ships the first synchronous source-workspace vertical:

    SourceTree uses the stable utf8-tree-v1 representation. PatchProposer accepts one exact-file command, while PatchResult carries the same evidence, usage, metadata, failure, and derivation information as an ordinary proposal. A decoded-value runner preserves the original callable path; the coordinator does not branch on either runner.

    DirectoryWorkspaces copies immutable source into a fresh private directory, captures through the same source validation, and disposes before result commitment. A disposal failure is an infrastructure failure and prevents success commitment because M5.1 has no honest mixed success-plus-infrastructure-warning outcome.

    M5.2 ships the synchronous SandboxProvider, immutable ProcessSpec and ProcessResult, and the clearly named DevelopmentSubprocessSandbox. The POSIX adapter enforces an absolute executable, workspace-contained normalized cwd, exact declared environment, timeout, independent raw-byte output bounds, whole-process-group termination, and lifecycle cleanup. Policy, timeout, resource, and infrastructure failures remain typed; ordinary nonzero exits are not interpreted. Narrow clock and process-operation seams make precedence and cleanup behavior deterministic under test. It makes no claim to secure arbitrary untrusted code. Add Git worktrees only as an optimization.

    M5.3 ships CommandEvaluator, EvaluationEnvironment, and root-exported ProcessSpec. The evaluator is a declared local callable component and uses the existing callable-evaluator path. Its digest-backed component version commits the complete command, environment, scoring, adapter, and exit-protocol semantics. Task construction invokes a general optional evaluator validate_task hook after normalization; no concrete evaluator branch enters the coordinator.

    The adapter materializes only a SourceTree, runs the declared process, and always disposes the workspace. Exit 0 and 1 produce passing and failing metrics; other exits become EvaluatorFailure. Existing process failures stay typed and non-rankable. Environment and bounded process-result evidence remain separate from metrics, and evaluator usage receives process wall time without claiming coordinator-owned evaluation counts. Cleanup failure overrides prior completion while retaining its classification, evidence, and usage.

    The evaluator-owned grader remains outside the candidate mutation surface. The development sandbox still makes no hostile-code filesystem-isolation claim; stronger providers remain replaceable at the same structural port.

    M5.4 pins deterministic content digests and semantic outcomes, while treating measured wall time as occurrence data. Reopened durable storage supports best-artifact and lineage queries; cold resume of these local live components fails explicitly and without side effects. SDK-backed proposers now remain user-owned local callables; portable reconstruction of patch, command, and live SDK components remains later work.

    The M5-owned file audit splits patch-proposer core behavior from lifecycle/resume failures and sandbox declarations/contracts from process execution. Canonical design documents remain cohesive source-of-truth exceptions to the 300-line guideline, and unrelated pre-M5 suites are not refactored as part of this closure.

    Milestone 6: SDK proposer boundary proof¶

    Status: Shipped. M6 completed on July 28, 2026 by proving that native coding SDKs could participate through the ordinary proposer seam without a provider-shaped coordinator. The first-party adapters and extras were superseded on August 5 in favor of user-owned SDK callables; the obsolete provider capture archive was removed on August 6. This section records only the contract that remains part of the shipped architecture.

    Retained contract¶

    • ProposerContext carries exact objectives, randomness, pushed context, and an optional scoped experience reader without evaluator, budget, permission, or promotion authority.
    • A structural propose(parent, context) object and a plain callable use the same runner path, validation, typed failures, usage, evidence, and derivation records.
    • SDK authentication, sessions, tools, permissions, retries, structured decoding, and provider telemetry belong to the user-owned wrapper.
    • Meta-Evolve retains candidate validation, external evaluation, effective budgets, durable records, lineage, audited experience, and promotion authority.

    Removed surface¶

    There are no meta_evolve.claude or meta_evolve.codex modules, provider extras, compatibility shims, provider conformance fixtures, or generic live smoke directory. Current opt-in SDK demonstrations are milestone-owned experiments, such as the M8 harness driver, and add no core dependency.

    The retired adapter implementations and live measurements remain recoverable from Git history and the closed M6 issues. They are historical development evidence, not current tests, documentation fixtures, or acceptance gates.

    Milestone 7: cross-domain local v1¶

    Add the artifact registry and public extension contracts only after number, text, and code examples have exercised them.

    The common artifact envelope contains semantic kind, representation, schema, interfaces, payload reference, content digest, parent occurrences, and provenance. Domain names such as TextArtifact, GitTreeArtifact, and SkillSetArtifact are typed constructors or views rather than a required inheritance hierarchy.

    M7 P1+P2 formalized the SourceTree payload shape into an explicit codec protocol, ArtifactCodec (ports/codecs.py): every kind, including the default python-value, now resolves through a per-run CodecIndex (application/codecs.py) instead of a hard-coded dispatch. Declared interfaces resolve through the registered codec (Registry.artifact_interfaces), not through a new field on the Artifact envelope, so this added no durable schema bump — CURRENT_SCHEMA_VERSION is unchanged. Registry.register_artifact_type rejects every codec offered for an already-built-in (kind, representation) key — the built-in object included — so the then-four built-in keys (python-value/canonical-json, source-tree/utf8-tree-v1, text/utf8-text-v1, skill-set/utf8-tree-v1) remain non-overridable. The unit is the key, not the kind: a new representation of a built-in kind is a distinct key and registers like any other custom type.

    P3 added skill-set (domain/skill_set.py), the first kind to reuse another kind's representation and the first codec with a non-empty interfaces declaration (skill-documents/v1). SkillSet wraps SourceTree construction and adds one rule, layout: every path matches skills/<name>.md.     The purity allowlists are decisions, not accidents. Two properties are pinned by tests/test_application_purity.py, each with an explicit allowlist whose every member carries its justification in the test file itself, and each with a companion test that fails once a member stops being needed — so an exemption cannot quietly outlive its reason.

    • Imports. Application modules import no concrete adapter except storage.py (composes the default memory/filesystem/sqlite stores), unit_of_work.py (owns the atomic durable commit across both stores), run_support.py (constructs the callable-adapter runners for run and resume), and runtime.py (wires the public run() entry point). All four are wiring: something has to name the concrete implementations a default meta.run composes, and the allowlist exists to keep that set visible and small rather than to excuse it.
    • Type dispatch. Nothing calls isinstance against a concrete artifact type outside application/codecs.py and adapters/. The codec is the artifact-type dispatch — encode must refuse a value of the wrong type before it can become a payload — and adapters translate at the edge, where an external system's output first has to become a declared artifact value or a typed failure. The watched set is derived rather than listed: any class in meta_evolve.domain declaring string KIND and REPRESENTATION — the pair Task(artifact=...) reads — falls under the gate the moment it exists, and a guard test pins the derived set so a fifth artifact type is a visible decision rather than a silent widening.

    P5a added the milestone's one new storage surface, the read-only listing Storage.runs() -> tuple[RunId, ...], so the CLI's list verb (and any caller whose ids have left the terminal scrollback) can reach Run, resume, and compare again. Two decisions are worth recording.

    Enumeration is an optional capability, not a widened port. EventStore keeps exactly append and read; the listing is a separate one-method protocol, ports.RunIndex, that both bundled stores implement. Both required methods are run-scoped, so an implementation can be addressable without being enumerable — one stream handed in at construction, a backend exposing only GET /runs/{id}/events, a store sharded so that "all runs" spans shards. Requiring enumeration of every implementation would earn complexity from a hypothetical rather than the current gate, and would break the hand-built Storage(artifact_store, event_store) pair that LocalOnlyUnitOfWork exists to serve. Storage.runs() checks isinstance(self.events, RunIndex) and raises CapabilityError otherwise; it never reports a non-enumerable store as an empty one. This follows the is_durable principle — a capability is declared by the component, never inferred from a concrete type — but not its mechanism: durability needs a separate boolean because it is invisible in a commit strategy's method set, whereas here the capability is the method, so implementing it is the declaration and a parallel flag could only disagree with it.

    Ids, sorted. The listing returns RunIds rather than a richer record: Run.summary() already owns per-run detail, and a richer listing would force the SQLite backend to decode every envelope just to enumerate. Ordering is lexicographic by id, not insertion — in-memory insertion order is a dict accident and SQLite has no insertion column short of rowid, an implementation detail unstable across VACUUM and interleaved appends. Sorting makes the two backends provably agree, which is the property callers depend on. Run ids are run-<sha256>, so the order carries no chronological meaning and is documented not to.

    P5b added meta_evolve.cli and the meta-evolve entry point: five verbs — run, list, inspect, resume, compare — over the same public API, using stdlib argparse, no configuration DSL, and no capability logic of its own. A run takes an experiment module exposing one experiment() factory with no import-time side effects; the command line supplies only --storage and --mode. M10.1 made the factory's return a typed Experiment; dictionary returns remain 1.x compatibility with a DeprecationWarning. list is one verb beyond the milestone's four because run ids are content-derived digests rather than names anyone retypes from memory: without enumeration, every other verb is unreachable once an id leaves the terminal. Exit codes are 0 for success, 1 for a domain failure (RunError), and 2 for a usage or experiment-module error; anything else keeps its traceback rather than being flattened into a message.

    Closed by the M7 defect-repair pass. compare_runs previously refused two incompatible runs with a bare ValueError from _require_equal (application/comparisons.py), which is not a RunError and so escaped the command line's typed-failure translation, reaching the user as a traceback. _require_equal now raises RunsNotComparable, a RunError carrying the declaration that differed as structured data rather than only in its message. The message text is unchanged, so prose matching still works; the command line now reports it as one error line and exit code 1 like every other typed failure.

    The other four decisions of that pass. The surfaces themselves are docs/programming-model.md's; what is recorded here is why each landed the way it did.

    • One accessor, not a second view type. Run.trials() returns the existing TrialView, which gained a state field set from the projection records rather than re-derived from other view fields. failure was deliberately left alone: splitting it is breaking, and it still could not express "unevaluated", which is an authorization outcome rather than a fault. The seed trial is included, because three of the six workarounds it replaced depended on unpacking it.
    • CapabilityError is reserved abort control flow, escaping both the proposer and the evaluator boundary unwrapped. RunError is deliberately not in either escape tuple: a nested evaluator may legitimately hit a RunError subclass while reading its inner run, and a broad escape would turn that into a crashed outer run rather than a typed evaluator failure carrying the usage already incurred. (This rationale once cited three examples calling summary() inside their evaluator; issue #143 moved all three to the failure-safe inspect().overview.task_usage, so that evidence no longer holds even though the decision does.) Because CapabilityError is publicly exported, the contract binds user code and is documented, not merely implemented.
    • The name-only report keys on the run-local version sentinel, never on origin == "local". CommandEvaluator is local-origin and versions itself with a configuration digest; keying on origin would condemn exactly the local comparisons that are controlled. ComponentRef.configured_local refuses that sentinel for the same reason, and derives origin and the retained adapter rather than accepting them, since Task's declaration hook admits a component only when it is local and holds that exact callable by identity.
    • Declarable turn limits keep their existing defaults exactly. The defaults emit byte-identical native profiles, so no component.version and no Claude run id moves. native_profile takes the limit keyword-required instead of choosing between two constants, so a normalizer and a transport cannot silently disagree about what was sent. Rejected: max(requested, PULL_MIN) — silently rewriting a chosen number is the defect class being removed.

    P6 published the conformance kit and the tutorial.

    Published conformance covers all seven component types. meta_evolve.conformance ships subclassable pytest suites, on the pandas ExtensionArray model, for artifact codecs (ArtifactCodecTests), repository-editing proposers (RepositoryProposerTests, PullRepositoryProposerTests), evaluators (EvaluatorTests), search programs (SearchProgramTests), context policies (ContextPolicyTests), workspaces (WorkspaceProviderTests), and sandboxes (SandboxProviderTests), alongside the MutationSurfaceTests that M8 introduced and M9 generalized to four surfaces.

    P6 shipped only the first two. M9 published SearchProgramTests, and the #98 follow-up closed the rest. Three of them existed as function-based suites under tests/ (policy_contract.py, workspace_contract.py, sandbox_contract.py) whose laws were already validated against a second implementation; converting those was exposure, not invention, and the function modules were deleted so a published suite and its retired twin cannot drift. policy_contract.py outlived M9's class suite because that suite took a policy instance, which cannot express a program built around the proposer; SearchProgramTests now takes either an instance or a search_factory, so the function module could go and MinimalPolicy runs through the published suite like everything else.

    The two proposer suites are exercised by in-repository reference callables (tests/test_proposer_conformance.py) — no first-party provider adapter ships, and the docs say so rather than implying one. The earlier claim that tests/ covered "both providers" had been false since the user-owned SDK boundary removed those adapters; the reference callables are what make it true again at the level a test can honestly pin. Evaluators and context policies had no reusable suite. ContextPolicyTests derives its laws from what the kernel already enforces, in bundle_violation. ContextPolicy.select receives the root-exported ExperienceGraph, and the query, node, record, and state values its methods exchange are root-exported as one closed read-only surface. Construction through replay_experience_graph remains an internal application service. EvaluatorTests is only partly of that kind: the objective-coverage and typed-failure laws follow adapters/evaluators.py, but stability, order-independence, and non-mutation are not kernel-enforced — they are obligations an evaluator can break today, which is why the suite is where they are stated. Only the store suite stays internal in store_contract.py: store adapters are not one of the seven extension families.

    The suites state their limits. ContextPolicyTests does not apply to NoMemory, which meta.run normalizes away before any policy runs, and asks a policy that selects nothing to declare it through expects_records — an empty bundle is accepted by the kernel, so refusing one outright would have been a law the shipped contract does not have. EvaluatorTests skips its typed-failure law visibly when a subclass declares no rejected_candidates.

    EvaluatorTests also keeps a candidate-mutation law that was first removed on the argument that it could never fail. That argument was wrong, and the counter-example is now a test: decode is only required to return an equal value, so a registered codec that hands back the instance it encoded gives the evaluator the caller's own object to edit. The root cause is closed at the codec end too, by ArtifactCodecTests.mutable_values. That fixture has no default — () is a positive claim of immutability, the same shape as rejected_values — because an opt-in law still certifies a codec whose author never considered aliasing. It cannot simply apply to every value: requiring decode(encode(v)) is not v unconditionally would fail the built-in python-value codec on interned small integers, where sharing is harmless. The subclass declares its mutable values outright; the evaluator's mutation law observes through the kernel content digest and needs no shared helper.

    The *_teeth test modules point a suite at a deliberately broken component and check its complaint, so a suite that stopped asserting would itself fail. They cover codecs, evaluators, search programs, context policies, workspaces, sandboxes, mutation surfaces, and — through broken reference callables such as a works-once proposer — the two proposer suites. They also pin the weaknesses review found: a workspace provider that leaks only when two workspaces are live, an evaluator whose drift hides in its uncertainty or evidence rather than its metrics, a sandbox that snapshots the environment in its constructor, a mutation surface that ignores the value it was asked to apply, a field that forges its own projection through __deepcopy__, a policy identity declared only for the kernel's read, a hidden random stream drawn only by the executed instance, an encode that special-cases the objects being watched, a value type whose __eq__ certifies a payload collapse, a sandbox that fabricates process results without executing, sandboxes that ignore timeout or either output limit, a sandbox that claims kernel-owned evaluation/trial/token usage, a random stream declared one decision late, a proposer that only works on its first call, a capture that re-reads only the paths it materialized, and a workspace backed by external symlinks.

    tests/ subclasses the published classes for every built-in codec, all four mutation surfaces, every shipped search program, both workspace and sandbox providers, every selecting context policy, and — via the reference callables recorded above — both proposer suites, so those suites and the kernel's own conformance are the same code and cannot drift. pytest is imported by that subpackage and nowhere else in the package, pinned by an AST scan plus a subprocess check that importing meta_evolve never loads it, and surfaced as the package's one optional extra, conformance.

    The codec suite checks round trips, rejection signaling, identity independence, repeated calls within one process, and common open/socket entry points. The last two are deliberately scoped evidence: they do not prove arbitrary purity or cross-process reproducibility. A separate built-in test creates artifacts in fresh interpreters under two fixed PYTHONHASHSEED values and compares their content digests.

    The artifact-domain guide contains a complete notebook experiment. tests/test_notebook_lessons.py executes the displayed cells and verifies their adjacent output, including execution outside the checkout with the installed package. tests/test_add_a_domain_tutorial.py checks decoded recipe values, independent grading, rejected proposals, and fresh-process reopening with a rebuilt codec registry but no original proposer or evaluator. It also runs the displayed codec through ArtifactCodecTests, including rejection of bare strings, unordered containers, and blank steps. The guide imports only the public root and the standard library. Custom domains remain local-only; saving and reopening do not grant resume capability.

    • Shipped — M10.4: application/inspection.py owns the immutable aggregate read model, while a shared application/views.py builder keeps artifact, evidence, trial-state, and lineage construction single-sourced. One Run.inspect() call performs exactly one validated replay.

    The dependency order is M10.0 → (M10.1, M10.3, M10.4, M10.5), M10.1 → M10.2, M10.1 + M10.4 → M10.6, M10.4 + M10.5 → M10.7, and M10.7 → M10.8.

    Core installation remains dependency-free. M10.7–M10.8 form the shipped bounded exception to the general dashboard prohibition, and only after M10.4 and M10.5 stabilize the public inspection, query, read-only storage, and version contracts. Its optional meta_evolve.browser package imports those public surfaces only—never Session, run, resume, proposers, evaluators, internal projections, or persistence implementations. cli.py conditionally imports it for the UI command. It binds to loopback, remains read-only, and exposes no operational, mutable, remote, collaboration, or distributed controls.

    The browser extra contains Starlette, Jinja, and Uvicorn: Starlette supplies tested routing and lifecycle, Jinja supplies escaped templates, and Uvicorn supplies server operation without bespoke web infrastructure. They do not enter core dependencies. Presentation itself remains dependency-free.

    Post-M10 presentation follow-up¶

    Status: Design—not shipped. This future slice owns notebook HTML representations over M10.8's shipped inert records and browser screenshot or visual-regression automation. The safe presentation boundary is a dependency, not permission to claim notebook rendering today. This work is outside the M10 closure gate and requires a separate implementation and acceptance gate.

    Milestone 11: trusted distribution¶

    Status: Design—not shipped. Tracked by #10.

    Only after local semantics are stable:

    • add WorkAttempt and durable lease acquisition, renewal, expiration, cancellation, and completion;
    • retain one logical Trial across delivery retries;
    • introduce trusted worker identities and capability matching;
    • add atomic budget reservation and settlement;
    • make idempotent result submission explicit;
    • define consistency requirements per state type;
    • load-test simulated populations before paid agent fleets.

    The canonical reservation is examples/research/trusted_workers/.

    Worker liveness and queue estimates are ephemeral. Accepted outcomes, evaluations, budgets, and promotion decisions are durable. Out-of-order wall-clock completion must not alter logical random choices or reveal future experience.

    Milestone 12: contributed and federated network¶

    Status: Design—not shipped. Tracked by #11 and dependent on M11.

    Add signed manifests, scoped contributor identities, task-specific trust policies, visibility, licensing, embargoes, attribution, retraction, disputes, and reputation. Exchange policy-filtered subgraphs rather than assuming universal access.

    References may be redacted, tombstoned, or inaccessible while preserving enough metadata to maintain causal structure. Untrusted execution, evaluator collusion, poisoning, sybil attacks, reward hacking, and correlated replication remain separate threats with separate controls.

    The canonical reservation is examples/research/federated_exchange/.

    Interface staging¶

    Capability First implementation Later implementation
    Proposer local callable SDK agent, human workflow, composite harness
    Evaluator pure callable isolated grader, simulator, proof checker
    Artifact store in-memory payloads content-addressed filesystem or object store
    Event store in-memory list SQLite, then durable service
    Search greedy and best-of-N populations, Pareto, islands, learned allocation
    Experience no memory exact graph traversal, then measured semantic retrieval
    Workspace absent directory copy, Git tree/worktree, remote volume
    Sandbox absent development subprocess, container, hardened remote sandbox
    Identity absent or local stub trusted worker, then signed contributor identity

    What not to build first¶

    • every module in the destination package tree;
    • a custom graph or vector database;
    • a peer-to-peer protocol or token economy;
    • a thousand-agent deployment;
    • mutable, operational, or remote dashboards, and any browser before stable public event and query contracts;
    • universal agent communication;
    • learned scheduling without strong baselines;
    • unrestricted self-modification;
    • a template DSL when local closures and typed durable manifests suffice;
    • scientific-discovery claims without domain evidence and replication.

    Near-term definition of done¶

    Meta-Evolve has a credible first release when a user can define a task, seed artifact, proposer, and evaluator through the canonical small API; choose a search and context policy; run callable and SDK-backed proposers in appropriate execution profiles; evaluate immutable successors; inspect exact causal experience; resume durable runs after failure; and compare runs under equal budgets.

    Everything beyond that should extend the same contracts rather than replace the kernel.
