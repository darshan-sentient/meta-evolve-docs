    Improve an agent's harness¶

    A harness configures an agent's instructions and context. Here, you will improve a tiny help assistant's question matching and available help notes, check fresh questions, and export its configuration: an example of meta-evolution.

    The assistant and revisions are handwritten Python. The assistant recognizes two explicit instructions; it does not understand arbitrary prompts. No model, API key, checkout, or earlier notebook is needed.

    1. Install¶

    Open a notebook with Python 3.12 or newer. Download the package ZIP into its working folder, then copy the Python blocks into cells in order. Restart the kernel if your notebook asks. For hosted notebooks, upload the ZIP through the file browser; %pwd shows the working folder.

    %pip install ./meta-evolve.zip

    2. Declare what can change¶

    HarnessArtifact holds the starting configuration, our seed. TextParam holds planner instructions for matching questions; PolicyParam holds context settings that decide whether the assistant receives billing help.

    ComponentRef names the component, role, and version; interface labels describe the values its consumer understands. These declarations stay fixed while text and settings change. They identify components without loading an agent.

    import meta_evolve as meta
from meta_evolve import harness
from meta_evolve.domain import ComponentRef

baseline = harness.HarnessArtifact(
    planner=harness.TextParam(
        name="planner",
        component=ComponentRef(role="planner", name="help-matcher", version="1"),
        interface="help-matching/v1",
        value="Match exact questions.",
    ),
    context_policy=harness.PolicyParam(
        name="context_policy",
        component=ComponentRef(
            role="context-policy", name="help-notes", version="1",
        ),
        interface="help-context/v1",
        configuration={"include_billing": False},
    ),
)

    3. Connect the configuration to an assistant¶

    answer receives only a question and a harness. Its reference notes are separate from the evaluator's test questions. Exact matching requires the entire question to match; topic matching accepts extra words around the topic's words. An unsupported instruction raises an error. Finding no note returns an ordinary answer that the evaluator can grade.

    def answer(question, candidate):
    notes = [("reset password", "Open Settings > Password.")]
    if candidate.context_policy.configuration["include_billing"]:
        notes.append(("download invoice", "Open Billing > Invoices."))

    instruction = candidate.planner.value
    if instruction not in ("Match exact questions.", "Match topic words."):
        raise ValueError("Unsupported matching instruction")

    question = question.lower()
    for topic, reply in notes:
        if instruction == "Match exact questions.":
            matches = question == topic
        else:
            matches = set(topic.split()) <= set(question.split())
        if matches:
            return reply
    return "I don't have a matching help note."

print(answer("reset password", baseline))
print(answer("please reset password", baseline))
# Output:
# Open Settings > Password.
# I don't have a matching help note.

    4. Grade answers independently¶

    Development cases are questions used during search. The evaluator calls the assistant and checks its returned answer against a fixed expectation. It grades behavior, rather than awarding points for a particular instruction or setting.

    development_cases = (
    ("reset password", "Open Settings > Password."),
    ("please reset password", "Open Settings > Password."),
    ("download invoice", "Open Billing > Invoices."),
)

    make_evaluator binds cases to a grading function. EvaluationResult reports the fraction correct as score; EvidenceDraft retains each answer and check. An execution error becomes a failed evaluation with no score.

    The final lines give the evaluator a configuration identity: a SHA-256 fingerprint of its cases and Python source, including the assistant's notes. ComponentRef.configured_local attaches that identity to the callable. This lets the comparison later refuse runs whose grading setup differs.

    from hashlib import sha256
from inspect import getsource

def make_evaluator(cases):
    cases = tuple(cases)
    worker = answer

    def evaluate(candidate):
        checks = []
        for question, expected in cases:
            actual = worker(question, candidate)
            checks.append({"question": question, "expected": expected,
                           "actual": actual, "passed": actual == expected})
        return meta.EvaluationResult(
            metrics={"score": sum(c["passed"] for c in checks) / len(checks)},
            evidence=(meta.EvidenceDraft(
                kind="help-checks", data={"checks": checks},
            ),),
        )

    source = repr(cases) + getsource(worker) + getsource(evaluate)
    evaluate.component = ComponentRef.configured_local(
        "evaluator", evaluate, name="help-answers",
        version=sha256(source.encode()).hexdigest(),
    )
    return evaluate

    5. Propose one change at a time¶

    A proposer receives the parent harness and returns a revision. HarnessMutation names the part to change and its replacement value. parent.apply() constructs a new harness without modifying the parent. It returns a typed failure for an invalid request, including a no-op.

    Our proposer first relaxes matching, then includes billing notes. These two handwritten proposals use only the parent configuration, without expected answers.

    def propose_harness(parent):
    if parent.planner.value == "Match exact questions.":
        mutation = harness.HarnessMutation("planner", "Match topic words.")
    else:
        mutation = harness.HarnessMutation(
            "context_policy", {"include_billing": True},
        )
    return parent.apply(mutation)

    Meta-Evolve also validates proposed successors before storing them. Changing component identities or interfaces is rejected even if a proposer constructs a harness directly. The evaluator, budget, and comparison rules stay outside the candidate. See the harness contract.

    6. Run and inspect development search¶

    Task declares the evaluator and artifact type. Experiment bundles it with the seed, proposer, and search. Greedy(max_trials=2) allows two proposals, each based on the best harness so far. meta.run evaluates the seed and revisions, recording the history. One evaluation checks all three development questions.

    harness_experiment = meta.Experiment(
    seed=baseline,
    task=meta.Task(
        artifact=harness.HarnessArtifact,
        evaluator=make_evaluator(development_cases),
    ),
    proposer=propose_harness,
    search=meta.Greedy(max_trials=2),
)
harness_result = meta.run(harness_experiment)

for attempt in harness_result.trials():
    if attempt.failure:
        print(attempt.failure.kind)
    else:
        print(f"{attempt.metrics['score']:.0%}")
print("Evaluations:", harness_result.usage().evaluations)
# Output:
# 33%
# 67%
# 100%
# Evaluations: 3

    The seed answers only the exact password question. Topic matching fixes the polite version. Adding billing notes fixes the invoice question. best() gives the selected artifact view; .value is its harness configuration. best_trial() gives its evaluation and retained checks.

    selected = harness_result.best()
print(selected.value.planner.value)
print(dict(selected.value.context_policy.configuration))
checks = harness_result.best_trial().evidence[0].data["checks"]
for check in checks:
    print(check["question"], "->", check["actual"])
# Output:
# Match topic words.
# {'include_billing': True}
# reset password -> Open Settings > Password.
# please reset password -> Open Settings > Password.
# download invoice -> Open Billing > Invoices.

    7. Check fresh questions after selection¶

    Held-out cases are separate questions used only after choosing a harness. Create two fresh runs: one for the unchanged baseline, one for the selection. Greedy(max_trials=0) evaluates each seed once without calling the proposer. Both use the same task and evaluation budget, so only their harness differs.

    meta.compare_harnesses checks compatibility and reports improvement, tie, regression, or unrankable when a measurement is unavailable. Its promotion_eligible flag reports a strict improvement under those controls; your application decides whether to use it.

    from dataclasses import replace

held_out_cases = (
    ("reset my password", "Open Settings > Password."),
    ("download my latest invoice", "Open Billing > Invoices."),
)
held_out_task = meta.Task(
    artifact=harness.HarnessArtifact,
    evaluator=make_evaluator(held_out_cases),
    budget=meta.Budget(evaluations=1, trials=0),
)
held_out_experiment = meta.Experiment(
    task=held_out_task, seed=baseline, proposer=propose_harness,
    search=meta.Greedy(max_trials=0),
)
baseline_run = meta.run(held_out_experiment)
candidate_run = meta.run(replace(held_out_experiment, seed=selected.value))
comparison = meta.compare_harnesses(baseline_run, candidate_run)
print(f"Held-out: {comparison.baseline.quality:.0%}"
      f" -> {comparison.candidate.quality:.0%}")
print("Verdict:", comparison.verdict)
# Output:
# Held-out: 0% -> 100%
# Verdict: improvement

    Two questions demonstrate this procedure; they do not establish broad quality. The split follows execution order, with no isolation from untrusted Python. The two fresh runs add two evaluations, for five total. Preview calls to answer are outside run accounting.

    8. Export and reuse the selected harness¶

    meta.export_harness writes the configuration and a manifest to a new folder. meta.load_harness validates and reconstructs it. Your application still supplies answer or its own agent implementation. Run history is saved separately.

    from pathlib import Path
from uuid import uuid4

if comparison.promotion_eligible:
    destination = Path(f"help-harness-{uuid4().hex}")
    exported = meta.export_harness(selected, destination)
    loaded = meta.load_harness(exported.destination)
    print("Loaded configuration matches:", loaded == selected.value)
    print(answer("please download my invoice", loaded))
else:
    print("No export: the held-out comparison did not show improvement.")
# Output:
# Loaded configuration matches: True
# Open Billing > Invoices.

    Each export uses a fresh folder. Save run history separately.

    Change and predict¶

    Change development search to Greedy(max_trials=1) and rerun from section 6. The selected harness can match extra words but still lacks billing notes: development reaches 67%, and held-out quality reaches 50%. The baseline stays at 0%. There are four evaluations overall.
