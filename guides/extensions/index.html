    Extensions¶

    Status: Shipped. Add replaceable components at declared seams; never branch the coordinator on a concrete domain, provider, evaluator, policy, or backend.

    Artifact domains¶

    An artifact codec declares a stable kind, representation, interfaces, canonical encode/decode behavior, and rejection boundary. Register it with Registry. The same codec encodes the seed and every successor; rejected values become typed invalid-output trials.

    The complete artifact-domain tutorial is extracted, executed in a clean interpreter, and checked against the published codec conformance suite.

    Components and identity¶

    Local callables are convenient but not cold-resumable. Registered durable-local proposers, evaluators, search policies, and context policies use explicit component references plus behavior-affecting configuration. Resume rebuilds the recorded implementation from that registry and refuses mismatches.

    Published conformance¶

    Every extension component family has a published reusable suite: codecs, repository-editing proposers, evaluators, search programs, context policies, workspaces, sandboxes, and typed mutation surfaces. Subclass one, name the subclass Test..., and override its fixtures and hooks. Each runs unchanged here against the built-in implementations (or, for the proposer suites, reference callables) plus at least one written the way an outside author would write it — MutationSurfaceTests against TextParam, PolicyParam, ParentSelection, and TrialLimit; SearchProgramTests against Greedy, BestOfN, BestOfK, Population, CandidatePolicy, and a next-only custom program.

    The two proposer suites are exercised by in-repository reference callables (tests/test_proposer_conformance.py); no first-party provider adapter ships, so those callables are the reference subjects.

    SandboxProviderTests checks the declared cwd and exact environment, verbatim argv, separated output streams, ordinary nonzero exits, enforced timeout, independent stdout/stderr byte ceilings, bounded partial output, and wall-only usage. Its timeout and probe-sleep fixtures are overridable for container and remote startup costs. Passing it does not prove filesystem isolation or that a provider executed rather than simulated every probe; CPU, memory, network, syscall, and broader execution isolation remain outside the suite.

    ContextPolicy.select receives a typed, read-only ExperienceGraph. Import ExperienceGraph and ExperienceQuery from meta_evolve; the returned ExperienceNode, ExperienceRecord, and ExperienceState values are root exports too. Replay construction remains an application service, so helpers such as replay_experience_graph stay under meta_evolve.application.

    State the limits rather than implying coverage that does not exist. A suite checks the laws it names and no others, and it makes an unexercised law visible: EvaluatorTests skips its typed-failure check when a subclass declares no rejected_candidates and its semantic oracle when it declares no scored_candidates, ArtifactCodecTests skips its aliasing law when mutable_values is () and its decode-validation law when rejected_payloads is (), and ContextPolicyTests makes a policy that selects nothing say so through expects_records. NoMemory is outside that suite, since meta.run normalizes it away before any policy runs.

    The subclass contract follows one rule set, stated in the package docstring: required hooks raise NotImplementedError; optional laws skip visibly or cross-check a declaration; a law needing an uncontaminated second subject asks for a factory (make_evaluator, search_factory) and refuses the same object twice; laws observe subjects through kernel records or author-supplied projections, never the subject's own equality or self-report.

    One trap is worth knowing when you write a codec: decode returning an equal value is not the same as returning an independent one. A codec that hands back the instance it was given lets an evaluator reach and edit the caller's own object. ArtifactCodecTests.mutable_values has no default for that reason — declaring () is a positive claim that your values are immutable, not a way to skip the question. Every value law observes through value_state, an observation the codec has no hand in — never through the value type's __eq__ (which usually ships with the codec and could certify a collapse) and never through the codec's own encode (which could special-case the watched objects); the default projection knows exact canonical and kernel types and refuses anything else. Mutable values additionally require mutate, the edit the aliasing law watches. rejected_payloads is the mirror of rejected_values on the decode side — decode is validation, and () is a positive claim that every payload decodes. EvaluatorTests.scored_candidates is the analogous semantic oracle: every other evaluator law holds for lambda c: 0.0, so state expected metrics wherever your scores are predictable. EvaluatorTests keeps a matching candidate-mutation law, so the failure is caught where it starts and where it does damage.

    Store adapters keep an internal contract under tests/ and are not one of these families. The operations lab holds the coverage table.

    Migrating pre-1.0 conformance subclasses¶

    The strengthened codec and mutation-surface laws intentionally changed their subclass fixtures. There are no compatibility aliases: update subclasses so the new laws run instead of silently retaining the weaker contract.

    For codecs, rejected_payloads and mutable_values are now required. value_state must project custom values the default inert projection cannot read, and mutate is required only when mutable_values is non-empty.

    Before:

    class TestRecipeCodec(ArtifactCodecTests):
    @pytest.fixture
    def codec(self): return RecipeCodec()

    @pytest.fixture
    def values(self): return (Recipe(["mix"]),)

    @pytest.fixture
    def rejected_values(self): return (7,)

    After:

    class TestRecipeCodec(ArtifactCodecTests):
    # codec, values, and rejected_values stay as above
    @pytest.fixture
    def rejected_payloads(self): return (7, None)

    @pytest.fixture
    def mutable_values(self): return (Recipe(["mix"]),)

    def value_state(self, value): return tuple(value.steps)

    def mutate(self, value): value.steps.append("bake")

    Return () from mutable_values for an immutable value type and omit mutate. Return () from rejected_payloads only when every canonical payload is valid input to decode; both empty tuples are positive claims.

    For mutation surfaces, replace the singular mutation plus expected_surface fixtures with plural (mutation, expected_successor) pairs, and replace invalid_mutation with invalid_mutations.

    Before:

    @pytest.fixture
def mutation(self): return Rename("new")

@pytest.fixture
def expected_surface(self): return NameParam("new")

@pytest.fixture
def invalid_mutation(self): return Rename(7)

    After:

    @pytest.fixture
def mutations(self):
    return ((Rename("first"), NameParam("first")),
            (Rename("second"), NameParam("second")))

@pytest.fixture
def invalid_mutations(self):
    return (Rename(7),)

    Keep surface, no_op_mutation, and foreign_mutation unchanged. Supply more than one valid pair wherever the domain allows, so an implementation that accepts one fixture value but substitutes its own value for others cannot pass.

    Design rule¶

    Introduce a protocol only when a current acceptance test needs an independently testable second implementation. Keep the public call smaller than the internal port, preserve immutable inputs and typed failures, and make authority and accounting explicit.

    The generated API reference lists every shipped root name and the namespaced harness and policy families. See the harness evolution and policy evolution guides.
