    User-owned SDK integration¶

    Continue the meeting-notes tutorial by replacing its two model functions. Any SDK uses the shipped callable boundary; Meta-Evolve does not install, authenticate, configure, or wrap a model SDK.

    Start with the ordinary callable¶

    Run the complete demonstration from the repository root after the tutorial setup. It needs no credentials or model SDK:

    uv run python examples/learn/meeting_notes/model_integration_demo.py
    Output
    All responses and telemetry are synthetic: no SDK requests or actual charges.
Selected prompt: Extract agreed or explicitly needed action items as a JSON array. Use task phrases from the notes with fields task, owner, deadline. Use null for unstated owners or deadlines. Exclude unaccepted suggestions. Include every needed task, including unassigned work in mixed notes.
Development result: 6/6
Development calls: 18 responses + 2 rewrites
Synthetic development usage: 148 tokens, 64 spend-micros, 5.5 seconds
Separate reserved check: 3/3
Additional response calls: 3
Synthetic reserved usage: 21 tokens, 9 spend-micros, 0.75 seconds
Development history unchanged: True

    The complete demo source contains FakeClient, its recorded requests, both wrapper implementations, and the reporting above. The fake returns handwritten responses and synthetic usage: these numbers demonstrate accounting, not model performance or actual expenditure. Integration tests import this same client.

    Replace the meeting-notes fixtures¶

    Keep the evaluator, feedback selection, and two-attempt Greedy search in model_integration.py. Replace only the two callables:

    • respond(prompt, notes) returns extraction response text in meta.ProposalResult(candidate=...), or a typed failure, with known usage and evidence. It receives one prompt and one note, without grading answers.
    • rewrite(parent, report) returns a nonempty replacement prompt in meta.ProposalResult, or a typed failure, with known usage and evidence. Its JSON report contains authorized failed development cases, including the notes, response, expected annotation, and reason. Reserved cases never enter it.

    The following is user-supplied SDK pseudocode: my_model is your module, not a bundled API. Save it beside the meeting-notes scripts after implementing those wrappers. Use the demo's source to see where requests and telemetry belong.

    import meta_evolve as meta
from model_integration import experiment
from my_model import respond, rewrite

result = meta.run(experiment(
    respond,
    rewrite,
    model_configuration={
        "response_model": "your-response-model-id",
        "rewrite_model": "your-rewrite-model-id",
        "wrapper_revision": "1",
        "temperature": 0,
        "timeout_seconds": 30,
        "max_output_tokens": 500,
        "retries": 0,
    },
))
print(result.best().value)

    Importing or constructing experiment(...) makes no model calls. There is no source-tree staging or nested run. The integration tests check request order, authorized feedback, accounting, and final-check separation.

    Declare all settings that affect behavior, including both model identities when they differ, sampling settings, wrapper revision, and enforced limits. Configured component identities include this mapping and the composition and evaluation implementation inputs. Configuration declares identity; your wrappers must enforce the settings themselves. Changing model or wrapper settings makes runs incomparable. A wrapper implementation change needs a new declared revision.

    The default experiment permits at most 20 development wrapper calls: 6 notes × (1 seed + 2 revisions) + 2 rewrites. The demo then makes three separate response calls on reserved cases, after selection. That final check has its own usage and does not enter development history, feedback, or selection. The complete source shows the ordinary evaluator call; it does not create another run.

    Retries can add provider requests inside a wrapper beyond those 20 + 3 calls. SDK installation, authentication, sessions, permissions, timeout and retry enforcement, decoding, provider configuration, and telemetry remain user-owned. Report all known usage across retries. Monetary accounting is post-hoc enforcement, not a reservation-based hard spending cap.

    Malformed extraction JSON is an observed failed case. An unavailable response is a failed measurement with no score; return its typed failure with known usage and evidence. The example also retains telemetry when rejecting non-string responses, forbidden coordinator counts, and empty or whitespace-only rewrites. ExecutionAccountingUnknown propagates from either callable. The three failure cases below explain when to return a failure and when to raise; there is no fallback response. Store recorded responses for inspection: a later live call need not regenerate them, and fixture scores do not predict model performance.

    Return a typed result¶

    Use ProposalResult when the wrapper has more to report. This and the my_sdk tool example below are user-supplied SDK pseudocode:

    def propose(parent, context):
    response = my_sdk.generate_structured(input=parent)
    return meta.ProposalResult(
        candidate=response.artifact,
        usage=meta.Usage(
            tokens=response.input_tokens + response.output_tokens,
            # Charged spend is shared usage; estimates stay evidence.
            spend_micros=response.charged_micros,
            wall_seconds=response.elapsed_seconds,
        ),
        metadata={"model": response.model},
        evidence=(
            meta.EvidenceDraft(
                kind="sdk-response",
                data={"estimated_cost": response.estimated_cost, "raw": response.raw},
            ),
        ),
    )

    Total tokens, charged monetary spend, and elapsed time enter shared Usage. Model identity, estimated cost, granular token categories, and raw provider telemetry belong in evidence or metadata: only a figure the provider actually billed may become spend_micros.

    When a paid call fails, a wrapper has three cases, and the last is the one that is easy to miss:

    1. the provider returned exact usage — return a typed failure carrying that usage;
    2. the failure happened before any paid work — return a typed failure with zero usage;
    3. work may have started and exact usage is unavailable — raise ExecutionAccountingUnknown.

    The names come from two submodules:

    from meta_evolve.domain import InvalidOutput          # and the other failures
from meta_evolve.errors import ExecutionAccountingUnknown

    spend_micros is an integer, so convert before reporting — a float raises. Round up, so the framework never under-reports a charge, and keep the raw provider figure in evidence as provenance.

    Convert through Decimal, not by multiplying the float. Binary floats do not hold decimal amounts exactly, and the error goes the wrong way at exact micro boundaries: 0.000123 * 1_000_000 evaluates to 123.00000000000001, so a math.ceil of that produces 124 micro-USD for an amount that is exactly 123. Over-reporting money is a defect, not a safe direction.

    from decimal import Decimal, ROUND_CEILING, InvalidOperation

def charged_micros(cost_usd: object) -> int:
    """Exact micro-USD, rounded up, or refuse to guess."""

    try:
        # str() first: it yields the shortest decimal that round-trips the
        # value, so Decimal("0.000123") -- not the binary approximation.
        amount = cost_usd if isinstance(cost_usd, Decimal) else Decimal(str(cost_usd))
    except (InvalidOperation, ValueError, TypeError) as error:
        raise ExecutionAccountingUnknown(f"unreadable charge {cost_usd!r}") from error
    if not amount.is_finite() or amount < 0:
        raise ExecutionAccountingUnknown(f"invalid charge {amount}")
    return int((amount * 1_000_000).to_integral_value(rounding=ROUND_CEILING))

    NaN, infinity, and a negative amount are case 3, not zero: the call happened, so raise rather than book it as free.

    Decode the amount exactly, before it becomes a float. The conversion above is only as exact as its input, and str(float) recovers just the digits the float kept — by then 0.0001230000000000000000001 is already 0.000123, and rounding up gives 123 micro-USD instead of 124. A float cannot be repaired after the fact. So read the charge from the raw body:

    body = json.loads(response.text, parse_float=Decimal)
micros = charged_micros((body.get("usage") or {})["cost"])

    If your client hands you a decoded object rather than text, take the amount from somewhere exact — a Decimal, an integer, or a decimal string — rather than a float that has already been rounded.

    Never raise an ordinary exception after billing, and never return a bare Failure: both paths reach the adapter with no usage field, so the framework records zero and the charge is lost. This is a framework guarantee about those channels, not something conformance can detect on your behalf.

    Trial and evaluation counts are coordinator-owned; reporting either at the proposer boundary produces typed InvalidOutput. The meeting-notes evaluator rejects response-wrapper counts as a failed measurement, retaining known usage.

    At the proposer boundary, ordinary SDK exceptions become ProposerFailure. Framework failures about durable state, accounting, or run capability escape unchanged: EventStreamConflict, DurableCorruption, InvalidSearchHistory, ExperienceStoreUnavailable, ExecutionAccountingUnknown, and CapabilityError.

    Give an SDK audited pull tools¶

    When an SDK supports custom tools, register a user-owned handler that delegates to context.experience:

    used = []

def search_experience(arguments):
    if context.experience is None:
        raise meta.ExperienceAccessDenied("pull access was not granted")
    observation = context.experience.search(**arguments)
    used.extend(record.ref for record in observation.records)
    return observation

response = my_sdk.run(tools={"search_experience": search_experience})
return meta.ProposalResult(
    candidate=response.artifact,
    derived_from=tuple(dict.fromkeys(used)),
)

    The exact observation API is defined by ExperienceReader. The callback may run in process, or a user-owned RPC service may forward each request to this scoped handler and return its result. The RPC service must not cache or broaden the reader capability. Meta-Evolve adds no generic tool server or agent process.

    Access denial, exhaustion, audit-store failure, and unknown accounting retain their normal semantics because the SDK tool calls the authoritative reader. SDKs without custom-tool support can receive pushed context.bundle data, but that is context injection rather than agent-directed pull.

    The credential-free 06_user_owned_sdk example contains a complete deterministic fake SDK and audited tool callback. An acceptance-gated milestone may own an opt-in real-client experiment, as M8 does for harness validation. There is no generic provider smoke directory: a live script must serve a current gate, add no package dependency, and retain its single authorized outcome honestly.

    Authority and reproducibility¶

    The wrapper may propose candidate content. It cannot choose the evaluator, change the run budget, grant itself experience, edit audit history, or promote a result. External evaluation and durable storage remain the sources of score, accounting, and lineage truth.

    Committed requests, evidence, usage, failures, and artifacts support inspection and replay. Meta-Evolve does not claim that a later external SDK call will regenerate byte-identical output.

    API details: ProposalResult, ProposerContext, and EvidenceDraft.
