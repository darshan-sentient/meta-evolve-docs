    Local run browser¶

    Status: Shipped. M10.7–M10.8 provide an optional, read-only presentation over shipped Storage, inspection, artifact presentation, diff, comparison, and exact-version contracts.

    Start it¶

    Install the optional dependencies, then point the command at an existing durable store:

    uv sync --extra browser
meta-evolve ui --storage ./store --port 8000

    Runs using a custom artifact codec can reconstruct it through the ordinary experiment-module convention:

    meta-evolve ui --storage ./store --module experiments.my_run

    The optional module is loaded only after browser dependencies are available. Only its experiment().registry enters the browser reader; proposers, evaluators, policies, sessions, and execution are never invoked. Without the module or codec, the run is an ordinary actionable codec-unavailable 422 state rather than corruption.

    Open http://127.0.0.1:8000. The host is fixed to loopback and the server uses one worker. The browser has no write, run, resume, cancellation, promotion, or deletion controls. It has no authentication. Loopback binding limits its intended scope; it is not a claim that the application is safe to proxy or publish remotely.

    The pages are complete server-rendered HTML. Search, detail, comparison, lineage tables, and navigation work with JavaScript disabled. A small same-origin script only polls committed stream versions and reloads after facts change. A complete run page with a stable version carries no polling attributes at all; only the catalog and incomplete or unstable pages poll.

    What appears¶

    The catalog is ordered lexicographically by content-derived run ID; it makes no chronological claim. Cards show task identity, lifecycle, rankability, policy, the primary objective and available score, artifact kind, and usage. Search filters those recorded fields.

    A detail page follows the recorded story: overview, declaration, lineage, trials, evidence and failures, recorded artifact history, and decision timeline. The SVG lineage diagram has a semantic table containing the same parent edges. The history table preserves recorded occurrence order without calling it time, keeps occurrence identity separate from content digest, and offers one explicit diff choice for every parent.

    Artifact pages show identity, parents, bounded specialized presentation, exact canonical attachment, and every available parent diff. Text, source trees, skill sets, canonical Python values, harnesses, and policy artifacts have fixed views. A custom kind receives deterministic canonical-payload text and an explicit no-specialized-view notice. All content originates in the frozen payload; decoded ArtifactView.value is never read, stringified, or passed to templates. Evidence URIs remain inert text, never links.

    Direct-parent diffs support Text, SourceTree, and SkillSet. They identify added, removed, modified, and unchanged files and label added, removed, and unchanged lines textually as well as visually. A file whose content is identical on both sides reports its unchanged status without lines and consumes none of the shared diff budgets. Foreign-run views, non-parent edges, and incompatible families are refused with 422. Multi-parent occurrences never acquire an arbitrary default parent.

    Bounds apply in this order: lexicographic path sorting; first 100 entries; 64 KiB UTF-8 per retained preview document; 256 KiB aggregate preview input; 64 KiB per diff side and 256 KiB aggregate diff input before invoking the diff algorithm; then 4,000 output lines. Final partial and omitted states remain visible. Canonical downloads are not truncated.

    Comparison always receives an explicit ordered pair and invokes the public Run.compare() contract. It reports score, usage, winner or tie, and the three declaration flags. Incompatible or unrankable pairs remain visible as typed refusals; the browser does not pre-filter candidates or turn failure into a score.

    Replay and caches¶

    One dedicated thread creates Storage.read_only(), performs every listing, version query, inspection, and comparison, and closes the handle. Route handlers and Starlette's general threadpool never receive it. This preserves SQLite connection affinity while concurrent HTTP requests queue safely.

    The first catalog request performs one validated replay for every discovered run. It keeps one lightweight card per run, stamped with the exact run_version it observed and replaced when a newer version appears, plus a 32-entry LRU of full inspections. Comparisons use a separate 32-entry LRU keyed by the ordered IDs and both exact versions. Eviction discards only derived views, never durable facts. Inspections retain each frozen payload beside the decoded object, without eagerly storing an additional serialized byte copy; payload-heavy runs therefore consume proportionally more memory inside the bounded LRU. A comparison cache miss pays the public API's full multi-replay cost.

    Before replay, the reader polls exact versions. Exact hits avoid replay; completed cached runs are not polled again. Catalog polling still calls Storage.runs() to discover additions and checks versions of incomplete runs.

    Inspection reads a version before and after replay. A mismatch is retried once. If commits continue, the valid inspection snapshot is served without a version label or cache entry. Comparison is stricter: both versions must remain stable across the complete public comparison. A second mismatch returns retryable 503 rather than presenting a mixed observation.

    Failures and safety¶

    Unknown or concurrently missing runs and artifact occurrences return 404. Comparison and diff refusals and codec capability gaps return escaped 422 pages. Transient store failures and unstable comparisons return 503. Corruption and unexpected defects return a safe 500 without a traceback or durable detail. A corrupt or codec-unavailable run becomes an isolated catalog error card so healthy runs remain reachable.

    Store-open and schema failures happen before the server binds and use the ordinary CLI domain-failure path. Responses include a restrictive content security policy, nosniff, no-referrer, and frame-denial headers. These defenses do not expand the browser beyond its local, unauthenticated scope.

    Raw artifact responses use application/json, nosniff, and Content-Disposition: attachment with a digest-derived filename. The bytes are the current digest encoding, canonical-payload-v1, not a native artifact export and not an unconditional promise for every future durable format.

    Manual visual review checklist¶

    For changes to browser templates or CSS, review the catalog, run, artifact, diff, refusal, truncation, and codec-unavailable fixtures with JavaScript disabled at both fixed viewports:

    • desktop: 1440 × 900;
    • mobile: 390 × 844.

    Record completion in the PR. Check heading order, landmarks, skip link, visible keyboard focus, native controls, textual status labels, contained wide tables and preformatted text, single-column mobile layout, and reduced-motion mode. Screenshot automation remains out of scope for this milestone.
