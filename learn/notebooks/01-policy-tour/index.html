    Understand search policies¶

    Status: Shipped.

    The first run showed the core loop without randomness. This chapter keeps that simple checklist long enough to explain what search actually controls. It adds uncertain number proposals only after the deterministic case is clear.

    Open the canonical executed notebook if you want to rerun its cells. The notebook begins at the number-search part; this standalone chapter adds the gentler checklist introduction first.

    What it teaches¶

    One improvement attempt contains two decisions that are easy to confuse:

    1. The search policy chooses a parent artifact.
    2. The proposer turns that parent into a new candidate.

    The evaluator measures the candidate. Search uses the retained evidence to decide what receives the next attempt.

    Search chooses parent → Proposer creates candidate → Evaluator scores it
         ▲                                                   │
         └──────── coordinator records the outcome ──────────┘

    Search does not rewrite artifacts or select the proposer's future parent.

    Stage 1: the deterministic checklist¶

    The artifact is the number of completed checklist items. The seed is 0, one proposal completes one item, and score is the resulting count.

    ITEMS = 3

def propose(parent, _context):
    return parent + 1

def evaluate(candidate):
    return candidate

    There is only one possible candidate from any parent:

    Parent Candidate Score
    0 1 1
    1 2 2
    2 3 3

    The common task declares what success and permitted work mean:

    task = meta.Task(
    evaluator=evaluate,
    objectives=(meta.Maximize("completed", satisfy=ITEMS),),
    budget=meta.Budget(evaluations=4, trials=3),
)

    The seed costs one evaluation. Three more fund the successor trials. No policy can exceed this ceiling.

    Greedy builds a chain¶

    experiment = meta.Experiment(
    task=task,
    seed=0,
    proposer=propose,
    search=meta.Greedy(max_trials=3),
)
result = meta.run(experiment)

    Greedy maintains one best-so-far artifact, called the incumbent. Because every candidate improves the checklist, each one becomes the next parent:

    0 → 1 → 2 → 3

    This is a chain. Greedy is useful when small improvements compose: fixing one issue makes a useful base for fixing the next.

    BestOfN makes independent attempts¶

    Now change only the search declaration:

    search=meta.BestOfN(max_trials=3)

    BestOfN always gives the proposer the original seed. The proposer therefore receives 0 three times and returns 1 three times:

           ┌─ 1
0 ─────┼─ 1
       └─ 1

    This is a star. The best artifact is 1, with lineage [0, 1]. Separate candidate occurrences remain separate recorded attempts even when their content is equal.

    BestOfN is useful when attempts should not build on one another—for example, sampling several independent answers or prompt drafts. It buys breadth, not multi-step refinement.

    The checklist exposes the key difference without any luck:

    Policy Parent for attempt 2 Can compose steps? Best here
    Greedy 1 Yes 3
    BestOfN 0 No 1

    Neither result means one policy is universally better. This particular problem requires composition, so its structure favors Greedy.

    Population keeps several possibilities¶

    Population retains a bounded ranked archive instead of one incumbent:

    seed
├─ candidate A ── successor
├─ candidate B
└─ candidate C ── successor

    That tree matters when branches may lead somewhere different. The checklist cannot produce useful diversity, so Population only adds machinery there. Its size limits retained candidates; tournament_size controls how strongly parent selection favors higher-ranked members.

    Practical rule: if attempts should be independent, start with BestOfN. If improvements compose, start with Greedy; use Population when losing alternatives may matter later. Confirm that choice with equal-condition evaluation evidence.

    Stage 2: add uncertain proposals¶

    Only now introduce the notebook's benchmark. The seed is 0, the target is 12, and a proposal adds one of -2, 1, or 5:

    TARGET = 12
MOVES = (-2, 1, 5)

def propose(parent, context):
    move = context.rng.choice(MOVES)
    return parent + move

def evaluate(candidate):
    return -abs(candidate - TARGET)

    The score is negative distance because the objective maximizes:

    Candidate Distance from 12 Score
    0 12 -12
    5 7 -7
    11 1 -1
    12 0 0

    Higher is better: -1 is better than -7, and 0 means the target was reached. This scoring trick belongs to this benchmark, not to Meta-Evolve itself; evaluators can return ordinary positive metrics too.

    What the RNG is doing¶

    context.rng is a recorded random stream supplied for that logical decision. The proposer uses it because this benchmark intentionally allows multiple moves from one parent.

    experiment = meta.Experiment(
    task=task,
    seed=0,
    proposer=propose,
    search=meta.Greedy(max_trials=8),
    random_seed=1,
)
result = meta.run(experiment)

    The root random_seed makes local choices repeatable. It does not:

    • determine what score means;
    • choose a parent on the proposer's behalf;
    • make a hosted language model deterministic;
    • turn replay into a fresh rerun.

    The checklist needed no RNG because its proposer had exactly one action. Here, randomness represents uncertainty in which candidate gets proposed.

    Read the three search shapes¶

    With eight successor trials:

    • Greedy can accumulate moves along one improving chain.
    • BestOfN can reach only -2, 1, or 5, because every attempt starts at seed 0.
    • Population can accumulate moves along several retained branches.
    for name, result in runs.items():
    summary = result.summary()
    print(
        name,
        f"score={summary.primary_score}",
        f"usage={summary.usage}",
        f"lineage={list(summary.winning_lineage)}",
    )
    Output
    Greedy score=0 usage=Usage(evaluations=6, trials=5, tokens=0, spend_micros=0, wall_seconds=0.0) lineage=[0, 5, 10, 11, 12]
BestOfN score=-7 usage=Usage(evaluations=9, trials=8, tokens=0, spend_micros=0, wall_seconds=0.0) lineage=[0, 5]
Population score=-2 usage=Usage(evaluations=9, trials=8, tokens=0, spend_micros=0, wall_seconds=0.0) lineage=[0, 1, 2, 7, 8, 9, 14]

    Greedy stopped early after satisfying score 0. The other policies used all nine evaluations. This single run demonstrates mechanism; it does not establish that Greedy is generally superior.

    The public result object lets us inspect the winner, score, causal path, and the seed evaluation without reading coordinator internals:

    result = runs["Greedy"]
summary = result.summary()
print("best:", result.best())
print("primary score:", summary.primary_score)
print("winning lineage:", list(summary.winning_lineage))
print("seed metrics:", dict(result.trials()[0].metrics))
    Output
    best: 12
primary score: 0
winning lineage: [0, 5, 10, 11, 12]
seed metrics: {'score': -12}

    trials() includes the seed and every attempted successor. lineage() keeps only the causal ancestors of the selected artifact. Rejected candidates and typed failures remain recorded even when they are absent from that winning path.

    What to notice¶

    • Parent selection and candidate generation are different responsibilities.
    • Greedy produces a chain; BestOfN produces a star; Population produces a tree.
    • The best policy depends on whether improvements compose and diversity matters.
    • Randomness belongs to a component that needs it; it is not mandatory setup.
    • The seed is evaluated before successor trials and therefore costs evaluation budget.
    • Search selects a best artifact inside a run; it does not externally deploy or promote that artifact.

    Interpretation questions¶

    1. Why does deterministic BestOfN stop at one completed checklist item?
    2. Why is Population unnecessary for that checklist proposer?
    3. Why can number-search BestOfN never reach 12?
    4. What is the difference between replay and rerunning with the same root seed?
    Answers 1. Every attempt expands seed `0`, and the proposer adds exactly one. 2. It cannot create different alternatives from the same parent, so there is no useful diversity to retain. 3. Every proposal is one move from `0`; the only reachable values are `-2`, `1`, and `5`. 4. Replay reads committed decisions and outcomes. Rerunning invokes components again and can diverge when external systems are nondeterministic.

    Change and predict¶

    First stay with the checklist. Change its proposer from parent + 1 to parent + 2 and set the target to 4.

    Predict before running:

    • Greedy reaches 4 through [0, 2, 4] and stops early.
    • BestOfN repeatedly proposes 2 from seed 0 and never reaches 4.
    • The distinction still comes from parent selection, not randomness.

    Then return to the unchanged number benchmark. The next chapter repeats it over many root seeds and explains what a fair policy comparison may claim.
