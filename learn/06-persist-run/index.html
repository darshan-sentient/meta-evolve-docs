    Persist a useful run¶

    Status: Shipped.

    Persist only after the run is worth keeping. The durable story has four steps: Storage.durable() can preserve an ordinary local run for later inspection; that alone does not make it resumable. Reconstructible mode="durable-local" adds a registry of verified components and is the form resume() can continue.

    uv run python examples/operations/crash_recovery/learning_story.py
    Output
    store: (2, 6)
reopen: (6, True)
resume: (True, True)
compare: (True, False)

    The runnable transcript uses the registered functions beside it:

    """Normalized transcript for store, reopen, resume, and compare."""

from pathlib import Path
from tempfile import TemporaryDirectory

import meta_evolve as meta

from main import build_components, build_task


with TemporaryDirectory() as temporary:
    storage = meta.Storage.durable(Path(temporary) / "history")
    components = build_components()
    task = build_task(components.evaluator)

    def start(random_seed):
        experiment = meta.Experiment(
            task=task,
            seed=0,
            proposer=components.proposer,
            registry=components.registry,
            search=meta.Greedy(max_trials=8),
            random_seed=random_seed,
        )
        return meta.run(experiment, storage=storage, mode="durable-local")

    first = start(0)
    second = start(1)
    print("store:", (len(storage.runs()), first.best().value))

    before_reopen = len(storage.events.read(first.id))
    reopened = meta.Run(first.id, storage)
    print("reopen:", (reopened.best().value, len(storage.events.read(first.id)) == before_reopen))

    resumed = meta.resume(first.id, storage=storage, registry=components.registry)
    print(
        "resume:",
        (resumed.id == first.id, len(storage.events.read(first.id)) == before_reopen),
    )

    comparison = first.compare(second)
    print("compare:", (comparison.winner is None, comparison.same_random_seed))

    1. Store¶

    Storage.durable() keeps artifacts and append-only transitions. The transcript stores two runs and selects 6.

    2. Reopen¶

    Run reconstructs a read-only result. The True confirms that asking for best() wrote no new event.

    3. Resume¶

    resume verifies registered components and the recovery frontier, retains the same run ID, and performs no already committed work. This transcript resumes an already completed run, so the second True means no additional work. To see unfinished work execute, run the companion:

    uv run python examples/operations/crash_recovery/main.py
    Output
    interrupted == uninterrupted: True  (6 == 6)

    It interrupts after committed work, reopens the partial record, and resumes only what is missing. The recovery notebook explains the interruption points.

    4. Compare¶

    Two equal outcomes with different random-seed declarations compare as a tie; the False keeps that independent-variable difference visible. Comparison reports evidence and never promotes a result.

    Change and predict¶

    Copy examples/operations/crash_recovery/ into a scratch directory first. Replace one registered function after storing a run in your copy. Predict that resume fails before doing work: the recorded manifest no longer describes the live component.
