    Choose what to try next¶

    You have time for two revisions of a duration parser. Should the second revision build on the best version so far, or start again from the original? A search policy makes that choice: it selects the version your proposer receives next. The proposer decides how to revise that version. Proposals and search explains why those are separate roles.

    You want to… Use
    Build on the best version Greedy, the default in improve()
    Start each attempt from the seed BestOfN
    Compare results and work trials(), best(), and usage()

    The proposer uses handwritten source revisions; Python executes and grades them. No model, SDK, or credentials are needed. The same source always gets the same revision, and no evaluation feedback is supplied to this proposer.

    To run this page: expand the required setup, copy its Python blocks into notebook cells, and run them from top to bottom. Then run the examples below in order. Every definition is here; no other page needs to be executed. Rerunning the cells repeats the same results.

    Required setup for a fresh notebook

    Install. Use Python 3.12 or newer. Download the package ZIP into your notebook's working folder. For hosted notebooks, upload it through the file browser; %pwd shows the working folder. The ZIP is also included in offline docs builds. Run this installation once; restart the kernel if asked before continuing.

    Starting source and instructions. SEED reads a duration's number but ignores its unit. CONTRACT tells the proposer what the parser should do.

    import meta_evolve as meta

CONTRACT = """Implement parse_seconds(text) for whole-number durations.
Inputs contain a number followed by s, m, or h, such as '30s' or '2h'.
Return the duration in seconds as an integer. Return only Python source.
"""

SEED = '''def parse_seconds(text):
    return int(text[:-1])
'''

    Evaluation. evaluate returns the fraction of six checks answered correctly. load_parser executes the source locally; use this evaluator with the reviewed, handwritten code shown here.

    CASES = (
    ("30s", 30),
    ("90s", 90),
    ("2m", 120),
    ("3m", 180),
    ("1h", 3600),
    ("2h", 7200),
)


def load_parser(source):
    namespace = {}
    exec(source, namespace)
    return namespace["parse_seconds"]


def evaluate(source):
    parse = load_parser(source)
    passed = 0
    for text, expected in CASES:
        actual = parse(text)
        if type(actual) is int and actual == expected:
            passed += 1
    return passed / len(CASES)


print(f"Starting score: {evaluate(SEED):.0%}")
# Output:
# Starting score: 33%

    Revisions. The simulated agent adds minutes support, then hours support.

    MINUTES = '''def parse_seconds(text):
    quantity = int(text[:-1])
    return quantity * 60 if text[-1] == "m" else quantity
'''

COMPLETE = '''def parse_seconds(text):
    quantity = int(text[:-1])
    seconds_per_unit = {"s": 1, "m": 60, "h": 3600}
    return quantity * seconds_per_unit[text[-1]]
'''

    Proposer. propose supplies the instructions and current source to the simulated agent. Its response depends on the source, so reruns repeat the same revisions without a hidden response counter.

    def agent(message):
    """Simulate source revisions, without a model or a call counter."""
    source = message.rsplit("Current source:\n", 1)[1]
    if source == SEED:
        return MINUTES
    if source in (MINUTES, COMPLETE):
        return COMPLETE
    raise ValueError("This simulation only recognizes the tutorial sources.")


def propose(source):
    message = f"{CONTRACT}\nCurrent source:\n{source}"
    return agent(message)

    1. Run with the default search¶

    meta.improve() evaluates the seed, asks your proposer for revisions, and evaluates each valid revision. Its default Greedy policy proposes from the best version measured so far. trials=2 allows two proposal attempts after the seed evaluation.

    result = meta.improve(
    seed=SEED,
    proposer=propose,
    evaluator=evaluate,
    trials=2,
)

    The returned run retains the versions and their measurements. best_trial() gives the selected version's evaluation; a scalar evaluator's result is stored under the metric name score.

    print(f"Selected score: {result.best_trial().metrics['score']:.0%}")
# Output:
# Selected score: 100%

    Greedy starts from SEED, then builds on MINUTES to reach COMPLETE. Now make that search choice explicit so we can change it.

    2. Make search configurable¶

    meta.Experiment groups the starting artifact, proposer, evaluation task, and search configuration into one declaration. meta.Task holds the evaluator and, by default, maximizes its score. meta.run() executes the declaration and returns the same kind of result as improve().

    This is the explicit form of the run above:

    experiment = meta.Experiment(
    seed=SEED,
    proposer=propose,
    task=meta.Task(evaluator=evaluate),
    search=meta.Greedy(max_trials=2),
)

greedy = meta.run(experiment)

    max_trials=2 is Greedy's proposal-attempt limit. It plays the same role here as trials=2 on improve(); the seed evaluation is additional.

    BestOfN starts every proposal from the seed. Python's replace creates a second experiment declaration with that search policy, keeping the seed, proposer, task, and other settings the same:

    from dataclasses import replace

independent_experiment = replace(
    experiment,
    search=meta.BestOfN(max_trials=2),
)
independent = meta.run(independent_experiment)

    3. See what changed¶

    trials() lists the seed evaluation followed by the attempted revisions. best().value gives the selected source, which we can load and try on "2h". usage() reports how many proposal attempts and evaluations each run performed.

    for name, run in (("Greedy", greedy), ("BestOfN", independent)):
    scores = [f"{attempt.metrics['score']:.0%}" for attempt in run.trials()]
    print(name, scores)
    selected_parser = load_parser(run.best().value)
    print("  '2h' in seconds:", selected_parser("2h"))
    print("  Proposal attempts:", run.usage().trials)
    print("  Evaluations:", run.usage().evaluations)
# Output:
# Greedy ['33%', '67%', '100%']
#   '2h' in seconds: 7200
#   Proposal attempts: 2
#   Evaluations: 3
# BestOfN ['33%', '67%', '67%']
#   '2h' in seconds: 2
#   Proposal attempts: 2
#   Evaluations: 3

    The second proposal explains the difference:

    Policy Source sent to the proposer Revision returned Selected parser
    Greedy MINUTES, the best version so far COMPLETE Handles seconds, minutes, and hours
    BestOfN SEED, the original version MINUTES again Handles seconds and minutes

    Both runs evaluate the seed and two revisions. BestOfN's repeated source still counts as a second proposal and evaluation. The counts above belong to each run; the manual seed check and the earlier improve() run are separate work.

    A parent is the version a proposal starts from. Greedy changes that parent when it finds a strictly better revision; a tie or regression leaves the best version in place. BestOfN keeps the seed as its parent while retaining the best measured result. Either policy can select the seed if no revision beats it.

    Use Greedy when you want later revisions to build on successful changes. Use BestOfN when you want separate attempts from the same starting point. A model can return different proposals for the same input, so this handwritten example explains the policies without establishing which will work better on your task.

    Change and predict¶

    Change both max_trials=2 settings in the search declarations to max_trials=1, then rerun those declarations and the comparison. Predict the scores and work counts first.

    Both policies now select the minutes revision at 67%, using one proposal and two evaluations each. Their first proposals have the same parent; their second proposals are where the choices differ. The earlier improve() result stays unchanged because it belongs to a separate run.

    Why does BestOfN repeat the same revision?¶

    BestOfN sends the original source each time, and this simulated proposer always returns the same answer to that source. Independent attempts can still repeat content; each attempt remains in history and consumes work.

    For your own experiment, replace SEED, propose, and evaluate with your starting value, revision function, and grading function. Compare policies with the same task and allowance before changing those other components. Additional presets, including population, specialist, and tree search, are described in the search reference.
