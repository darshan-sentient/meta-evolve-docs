    Research and Systems References¶

    This is a working map of neighboring ideas. Meta-Evolve should implement, compose, and compare these approaches rather than rename one of them as a universal solution. For a plain-language comparison with AlphaEvolve and GEPA's optimize_anything, see How Meta-Evolve compares.

    Claims about capabilities in these papers belong to the cited systems. Their inclusion here does not mean Meta-Evolve has reproduced their results.

    Experience and cumulative improvement¶

    Experience Graphs / Trellis¶

    Experience Graphs: The Data Foundation for Self-Improving Agents treats the causal state produced by long-horizon search—attempts, executable artifacts, prompts, tool outputs, rewards, siblings, search statistics, and lineage—as governed database state.

    Important implications for Meta-Evolve:

    • stateless agents can recover and collaborate through durable shared experience;
    • online search, causal traversal, semantic reuse, temporal reconstruction, observability, and training views operate over one logical model;
    • the system must preserve the state observed when a decision was made, not only final mutated search statistics;
    • experience retrieval is a policy with an exploration-versus-anchoring tradeoff;
    • derived skills and training views inherit provenance and access constraints.

    The paper reports preliminary domain-specific results for cross-session reuse in kernel optimization, including faster early convergence and fewer buggy nodes, while aggressive reuse reduced strategy diversity and missed the best final candidate. This motivates controlled context-policy experiments rather than a general claim that more memory always improves search.

    Trellis overlaps with Meta-Evolve's data plane, not its entire product scope. Meta-Evolve focuses additionally on programmable harness and search abstractions, execution adapters, contributed agents/evaluators/compute, verification, and federation.

    Programming and optimizing LM systems¶

    DSPy¶

    DSPy provides a declarative programming model for modular LM programs and optimizers that compile prompts and demonstrations against metrics.

    Meta-Evolve should integrate DSPy in both directions:

    • wrap a DSPy program as a versioned harness component;
    • use a DSPy optimizer for an inner prompt/program compilation loop;
    • expose Meta-Evolve examples and evaluators as DSPy-compatible data and metrics;
    • capture compiled programs as immutable artifacts;
    • let an outer Meta-Evolve policy compare DSPy with other optimizers.

    The boundary is: DSPy programs LM pipelines; Meta-Evolve programs and evolves populations of executable systems, including DSPy pipelines.

    GEPA¶

    GEPA uses reflective textual mutation and Pareto selection to optimize LM components from task feedback. It is a reference for TextArtifact mutation, evidence-aware reflection, and Pareto retention.

    Feedback Descent¶

    Feedback Descent motivates structured comparison feedback followed by feedback-derived prompt edits. The research lab isolates that mechanism without claiming to reproduce its results.

    AutoData¶

    AutoData motivates evolving data-generation recipes with solver-based quality signals. The local lab's same-model/different-context restricted/informed setup is explicitly a teaching simplification and confounder.

    EvoSkill¶

    EvoSkill motivates failure-driven discovery, consolidation, and held-out selection of reusable skills. Meta-Evolve expresses this as evolution of a shipped meta.SkillSet — one skills/<name>.md document per skill — rather than a special memory subsystem. examples/research/context_evolution demonstrates the representation; its README states per mechanism what it runs and what it omits — failure-driven discovery and a held-out selection split are among the omissions. It does not reproduce the paper's system, benchmarks, or reported gains.

    ACE¶

    Agentic Context Engineering motivates treating the context itself as the evolving artifact: incremental generation, reflection on execution feedback, curation of individual entries, and explicit consolidation, rather than rewriting one monolithic prompt. Meta-Evolve expresses this as a meta.Text artifact holding canonical, validated JSON whose items carry stable logical identities, so an entry can be amended or retired without losing its history. examples/research/context_evolution demonstrates all four deterministically, with a model-free reflector and curator; its README states that and the rest of the omissions per mechanism. It does not reproduce the paper's system, benchmarks, transfer results, or reported gains, and claims no cross-task transfer.

    Meta-Harness¶

    Meta-Harness moves optimization beyond prompts to the source code and control logic surrounding a fixed model. It motivates HarnessArtifact, typed mutation surfaces, full execution history, and external authority boundaries.

    Its agentic proposer can selectively inspect the source, scores, and execution traces of prior candidates through a filesystem instead of receiving only compressed feedback. Meta-Evolve preserves this agent-directed exploration as a scoped ExperienceReader capability alongside policy-pushed context, and examples/research/harness_evolution demonstrates it — as a mechanism, and only for one artifact type. A fixed evaluator publishes each evaluated harness's complete mutable surface values as a canonical three-file value indexed in its own evidence, and the trusted adapter opens exactly the offsets that index names, under a declared operation, result, record, and character budget that fails closed. There is no filesystem: nothing is mounted, no path is browsed, and no Git history is presented. A read-only filesystem projection for coding agents, and structured graph tools adding causal traversal, logical-time queries, and governance, remain future work. Meta-Evolve does not reproduce Meta-Harness's system, benchmarks, or reported gains.

    Self-Harness¶

    Self-Harness closes the loop Meta-Harness opens: an agent improves its own harness through three iterative stages — weakness mining over execution traces, proposal of diverse but minimal harness edits, and validation that accepts an edit only after regression testing. It reports relative gains of up to 132% across nine model/benchmark combinations on Terminal-Bench-2.0, SWE-bench Verified, and AppWorld, and observes that effective harness design is itself model-specific.

    examples/research/harness_evolution demonstrates the weakness-mining stage only, and only as a mechanism. A fixed development evaluator publishes harness-diagnosis/v1 evidence — verifier-grounded failure clusters, the invariants already passing, and one digest per declared surface — and a deterministic context policy projects every prior attempt, including the rejected and failed ones, from those committed records. Digests, not surface values: naming which surface an earlier attempt changed is a diagnosis fact, while reading what it changed it to is the separate audited-source concern the Meta-Harness note above describes — a pull the proposer makes through the audited reader, not a wider push.

    Three properties are Meta-Evolve's stricter translation, not the paper's requirements: an attempt that does not fit the declared bounds makes the bundle refuse rather than silently omit it, the proposer returns a typed unrankable failure instead of a low score, and private and held-out facts are excluded by construction because held-out evaluations publish no diagnosis at all.

    This does not reproduce Self-Harness's system, benchmarks, or reported gains. It runs a model-free fixture over two repair episodes, mines weaknesses from one fixed verifier, and claims no cross-model or cross-task transfer.

    AHE¶

    Agentic Harness Engineering attacks the same loop from the observability side, through three matched pillars: component observability gives every editable harness component a file-level representation so the action space is explicit and revertible; experience observability distills raw trajectories into a layered, drill-down evidence corpus an evolving agent can actually consume; and decision observability pairs every edit with a self-declared prediction, verified in the next round against task-level outcomes. Ten iterations lift pass@1 on Terminal-Bench 2 from 69.7% to 77.0%, and its ablations localize the gain to tools, middleware, and long-term memory rather than the system prompt — which the authors read as factual harness structure transferring where prose-level strategy does not.

    examples/research/harness_evolution translates the third pillar. Every proposal returns a closed manifest: the authorized observations it cites, one declared surface and its value, the development behavior the edit predicts will improve, and the regressions it puts at risk. The paper's manifest also carries an inferred root cause, and its loop intersects each prediction with the next round's task-level deltas to produce a per-edit verdict and roll back the edits that fail. This example does neither; a prediction here is recorded and auditable, not yet adjudicated.

    Three properties are Meta-Evolve's stricter translation, not the paper's requirements: citations resolve only against an ordered ledger of observations the trusted adapter itself authorized, so a model-written identifier is never a derivation; exactly one surface may change per proposal; and a manifest that cannot state all five fields is a typed unrankable refusal rather than a low score.

    This does not reproduce AHE's system, benchmarks, transfer results, or reported gains. It runs a model-free fixture over two repair episodes, evolves two declared surfaces rather than a file tree, and claims no cross-model, cross-benchmark, or cross-family transfer.

    Shepherd¶

    Shepherd is a runtime substrate that records an agent's model actions, tool calls, and environment changes as a reversible, forkable execution trace. Its unit of control is an execution in progress; Meta-Evolve's unit of evolution is an immutable artifact evaluated between trials. The two models are therefore adjacent rather than interchangeable.

    A useful composition would keep Meta-Evolve in charge of tasks, search, budgets, independent evaluation, lineage, and promotion while a user-owned Shepherd-backed proposer supplies isolated execution, retained workspace output, and trace-level evidence. Any such integration should begin as an external adapter experiment: the captured artifact remains durable truth, trace references are supporting evidence, and restored or forked execution must not bypass trial or usage accounting. Shepherd's visual-artifact notebooks are also a useful teaching reference for deterministic-first examples, optional live runs, and progressive disclosure of execution internals.

    Asari inference-stack optimization¶

    Asari's inference-optimization report describes many agents improving a pinned vLLM serving stack through a discover/build, evaluate, verify, and self-improve loop. It reports changes across kernels, schedulers, load balancing, and configuration, using hierarchical performance benchmarks, measurement-noise controls, and token-distribution correctness checks.

    A bounded Meta-Evolve version maps cleanly onto current seams:

    • a small SourceTree overlay holds candidate kernel and configuration edits;
    • a user-owned SDK proposer investigates and changes that overlay;
    • a custom evaluator builds it against an evaluator-owned base, verifies model behavior, and returns performance metrics, uncertainty, evidence, and usage;
    • context or audited experience exposes earlier profiler and failure evidence;
    • search retains alternatives while lineage records which evidence informed each change; and
    • an external decision, never the candidate, owns production promotion.

    The shipped CommandEvaluator is only a binary, single-metric exit-code adapter, so a trustworthy experiment needs a domain evaluator that parses repeated benchmark samples. A local sequential precursor is feasible, but a whole-stack implementation also needs typed mutation surfaces and portable episodes from M8 and M9, plus trusted parallel GPU workers from M11. Cross-run knowledge transfer must be introduced explicitly rather than silently widening M3's same-run experience boundary.

    Meta-Evolve does not reproduce Asari's results. The scoped future work is tracked in issue #118: start with one kernel on one trusted GPU, preserve null and negative results, and defer many-agent whole-stack optimization until its dependencies ship.

    Evolutionary and meta-level search¶

    Recursive self-improvement survey¶

    The Last AI Built by Humans surveys execution, strategy, experience acquisition, deployment adaptation, and meta-improvement autonomy. It identifies safe inheritance, autonomy attribution, and reliable verification as credibility problems. Our mechanism map relates these questions to retained history, component authority, and independent evaluation as supporting mechanisms, not proofs. Future critic evolution remains a proposal. Meta-Evolve does not claim any level merely from a deterministic fixture, and does not reproduce the survey’s reported results.

    AIDE²¶

    Weco's AIDE² report describes a bi-level experiment in which an outer autoresearch loop rewrites an inner research agent, evaluates each rewrite across heterogeneous tasks under a fixed cost, and selects using private scores. Its reported empirical claims belong to that system. Meta-Evolve's autoresearch teaching example demonstrates only the small nested-run, budget, evidence, and split boundaries; it is not a reproduction or evidence of recursive self-improvement.

    AlphaEvolve¶

    AlphaEvolve demonstrates coding-agent-driven evolutionary search for algorithmic and scientific problems. It is a reference for program artifacts, evaluator-guided evolution, and populations of executable candidates.

    FunSearch¶

    FunSearch combines LLM-generated programs with automated evaluation and evolutionary selection for mathematical discovery. It illustrates why executable artifacts and objective evaluators are powerful while also showing that the evaluator and representation bound the discovery process.

    OpenEvolve¶

    OpenEvolve is an open evolutionary coding-agent framework and useful implementation reference for program databases, evaluation, and search loops. Meta-Evolve should seek adapter compatibility where practical rather than duplicate APIs without benefit.

    EvoX¶

    EvoX motivates treating both solutions and the search strategy as evolving artifacts. This corresponds to nested task evaluation of PolicyArtifact and SearchProgram candidates.

    Group-Evolving Agents¶

    Group-Evolving Agents studies evolution at the level of composite agent groups and shared experience. It is relevant to TopologyArtifact, performance-novelty selection, and group-level mutation.

    Self-generated curricula and model updates¶

    Agent0 and Dr. Zero¶

    Agent0 and Dr. Zero explore proposer-solver co-evolution and self-generated curricula under verifiable rewards. They motivate explicit curriculum, checkpoint, training-job, and evaluator artifacts with separate validation boundaries.

    AERO¶

    AERO couples self-questioning, answering, criticism, and iterative model updates. It is relevant to synthetic-experience artifacts and external training loops consuming experience-graph views.

    Multi-agent code and workflow optimization¶

    CORAL¶

    CORAL is relevant to parallel coding agents, evaluated repository successors, shared knowledge, islands, and migration. In Meta-Evolve this becomes one GitTreeArtifact task configuration rather than the universal runtime model.

    Quality diversity and island models¶

    Quality-diversity methods, novelty search, MAP-Elites, Pareto archives, and island models are important baselines for maintaining heterogeneous strategies and avoiding premature convergence. They should be implemented as replaceable population and migration policies.

    Memory, provenance, and infrastructure¶

    MemGPT¶

    MemGPT frames agent memory as a hierarchy that moves information between limited context and external storage. Meta-Evolve's ContextPolicy operates at this transport boundary, while the experience graph defines durable causal search state beneath it.

    Graphiti and structured memory¶

    Graphiti is relevant to temporal knowledge graphs and dynamic synthesis of agent memory. Meta-Evolve additionally needs executable artifacts, objective rewards, search-policy state, training views, and causal sibling/path queries.

    Event sourcing and content addressing¶

    Event sourcing, temporal databases, MVCC/change-data capture, content-addressed storage, reproducible build systems, and scientific provenance systems provide established foundations for immutable facts, current projections, time travel, lineage, deduplication, and audit.

    Meta-Evolve should reuse conventional database and storage systems until its measured workload demonstrates a need for specialized physical design.

    Research questions for Meta-Evolve¶

    • When does heterogeneous agent diversity improve compute-normalized progress?
    • Which context policies accelerate reuse without suppressing novelty?
    • Which topologies and migration policies avoid premature convergence?
    • How should compute be allocated among exploration, exploitation, repair, synthesis, and replication?
    • Which graph features predict the value of expanding or abandoning a branch?
    • How do skills and discoveries transfer across models, harnesses, tasks, and domains?
    • Which consistency guarantees are sufficient for concurrent search?
    • How should access changes and retractions propagate into derived skills, datasets, and checkpoints?
    • Can learned or evolved search policies generalize to held-out task distributions?
    • When do nested improvement loops plateau, destabilize, or exploit evaluators?
    • What evidence and replication policies predict real scientific validity?
