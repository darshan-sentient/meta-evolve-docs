    Operations and extensions¶

    Status: Shipped.

    Start with two runs in one durable store:

    uv run meta-evolve run examples/operations/command_line/experiment.py --storage ./store
uv run meta-evolve run examples/operations/command_line/best_of_n.py --storage ./store
uv run meta-evolve list --storage ./store

    run imports one side-effect-free experiment() factory returning meta.Experiment and prints the new run's summary. list returns the stored run IDs. Use those IDs next:

    uv run meta-evolve inspect <greedy-run-id> --storage ./store
uv run meta-evolve compare <greedy-run-id> <best-of-n-run-id> --storage ./store

    inspect reports one summary, lineage, and best artifact. compare first checks that the task, initial artifact, budget, and proposer declarations are compatible. It then reports both runs and their winner. The BestOfN module reuses the first module's declarations so only search behavior changes.

    For an optional server-rendered view over the same read-only public queries:

    uv sync --extra browser
uv run meta-evolve ui --storage ./store --port 8000

    The local browser guide documents its fixed loopback scope, exact-version caches, rendering exclusions, and absence of authentication.

    The canonical examples/operations/command_line/ walkthrough pins this entire transcript through subprocess tests.

    Resume is a declared capability¶

    Create a reconstructable run, then resume it:

    uv run meta-evolve run examples/operations/command_line/resumable.py \
    --storage ./store --mode durable-local
uv run meta-evolve resume <run-id> \
    --module examples/operations/command_line/resumable.py --storage ./store

    The module registers source-digestible proposer and evaluator functions. On resume, its factory rebuilds the registry and the library verifies the recorded component identities. A local run may use durable storage and remains listable and inspectable, but it is not resumable.

    The command line adds no capability rules. It passes --mode to meta.run and lets meta.resume accept or refuse the recorded run. The programming model owns the five report-verb mappings, factory convention, modes, and exit codes.

    For a real interrupted-process workflow, continue with the examples/operations/durable_operations/ walkthrough.

    Add a local artifact domain¶

    The add-a-domain tutorial builds and executes a Recipe value, codec, registration, task, proposer, and evaluator. Its custom codec runs through the published codec suite.

    That codec is a live Python object. It has no durable component manifest. In M9, mode="durable-local" therefore accepts only the six built-in (kind, representation) keys and rejects a registered custom codec before writing events. There is no silent fallback to local execution.

    A custom-domain local run may still write to Storage.durable(...). After a restart, rebuild the same registry and open it through meta.Run(run_id, storage, registry=registry). This grants decoding authority only. It does not make the run resumable.

    The CLI cannot perform that reopening. inspect and compare accept no registry argument, so they can decode built-in domains only. Use Python for a stored custom domain. This is a reconstruction limit, not a codec or storage failure.

    Conformance: every extension component family¶

    Install the opt-in test extra before importing the published suites:

    uv sync --extra conformance

    meta_evolve.conformance publishes a reusable suite for each of the seven extension component families, plus the typed mutation-surface contract that M8 and M9 grew:

    Component family Reusable coverage today
    Artifact codecs Published ArtifactCodecTests
    Repository-editing proposers Published RepositoryProposerTests and PullRepositoryProposerTests; exercised by in-repo reference callables
    Evaluators Published EvaluatorTests
    Search programs Published SearchProgramTests; Greedy, BestOfN, BestOfK, Population, CandidatePolicy, and a next-only custom program
    Context policies Published ContextPolicyTests
    Workspaces Published WorkspaceProviderTests
    Sandboxes Published SandboxProviderTests; cwd/environment/argv/streams, timeout, independent byte bounds, partial output, and wall-only usage
    Typed mutation surfaces Published MutationSurfaceTests; four built-in implementations

    Store adapters keep an internal tests/store_contract.py. It is not one of those extension families and is not published from meta_evolve.conformance.

    Published means an extension author can subclass the suite from an installed package. Internal means repository tests reuse assertions that are not part of the installed extension surface. Every published suite is subclassed inside tests/ — the built-ins where they exist, and in-repository reference callables for the two proposer suites, whose first-party provider adapters were replaced by the user-owned SDK boundary (no provider adapter ships). The published-conformance section of the extensions guide owns suite contents and limitations. Its migration section shows the required pre-1.0 codec and mutation-surface fixture updates.

    A published suite states what it does not check as carefully as what it does. EvaluatorTests skips its typed-failure law, visibly, when a subclass declares no rejected_candidates; ArtifactCodecTests does the same for its aliasing law when mutable_values is (); ContextPolicyTests excludes NoMemory, which meta.run normalizes away before any policy runs, and asks a policy that selects nothing to declare it through expects_records rather than pass in silence.

    One law is easy to think redundant and is not. EvaluatorTests checks that scoring does not edit the candidate. With the built-in codecs an evaluator only ever sees a frozen value decoded from the stored payload, so it cannot reach the caller's object — but a codec is user-supplied, and one that returns the instance it was handed gives the evaluator the real thing.

    ArtifactCodecTests.mutable_values is how you say which of your values can be modified in place; the codec suite then checks — through your value_state and mutate methods, never through the codec's own encode — that decode hands back an independent object. Every value comparison in the suite goes through value_state rather than the value type's __eq__, and rejected_payloads demands the decode-side refusals that make "decode is validation" true. It has no default, like rejected_values — () is a positive claim that your values are immutable, not a way to skip the question. The law cannot simply apply to everything, because the built-in python-value codec decodes a small integer to the very same interned object and that is harmless. So the two suites cover the same failure from both ends: the codec law where the leak starts, the evaluator law where it does damage.

    Lab questions¶

    1. Why can a local custom-domain run survive on disk but still require the live registry to decode after restart?
    2. Which CLI verb first makes an interrupted run reachable when its ID never reached terminal output?
    3. If you implement a search program that has to be built around the proposer, which of SearchProgramTests' two fixtures do you override, and why can the other one not express it?
