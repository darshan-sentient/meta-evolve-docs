    Documentation maintenance review¶

    This records #299's page and test audit against the September 16, 2026 working revision of the #293/#295/#296 documentation. The API and milestone boundaries remain owned by the canonical contracts; this change adds no package behavior. Use editorial conventions for the ongoing workflow. This review is a migration record, not a growing page inventory.

    Compatibility review¶

    The pre-change ledger covered 170 destinations and 1,138 fragments. The previous route fixture covered 75 historical navigation destinations. Repository searches included Markdown, tests, source inclusions, notebook references, and research catalog/inventory origins. The latter explicitly retain references.md#... addresses as historical provenance. Current content links now use maintained pages directly; historical provenance addresses still resolve.

    The former parser lesson's detailed fragments now go straight to their retained live-parser explanations, including cost reporting and complete source. The unfragmented route still opens the introductory notebook. A working anchor at a generic next-step list would not answer those saved questions directly.

    There is no authoritative list of external bookmarks. All previously recorded paths and fragments therefore remain protected in the fixed tests/fixtures/documentation_routes.json baseline. No URL or recorded fragment is retired in this change. This includes anchors without current inbound links. The new redirect map carries explicit final destinations, including destinations on different pages. Its outputs remain relative for hosted subpaths and local serving, with usable links when JavaScript is disabled.

    An ordinary new page or heading needs no baseline entry. Renaming a heading with a supported old fragment can preserve that fragment as an explicit ID. A future retirement needs a reference audit and a recorded reason and replacement; simply deleting an assertion does not retire a promise.

    Previous obligation Replacement or retained guarantee
    Hook requires every page in dispositions Hook validates only redirects against actual files; a miniature strict build proves that a new guide needs no ledger or source stub.
    Invalid inventory rejects unlisted pages Replaced by positive new-page coverage and negative missing-target, duplicate, collision, chain/cycle, and invalid-fragment-map cases with diagnostics.
    Consolidation test checks every ledger heading Promised path/fragment checks move to the fixed compatibility fixture; removing an unlinked promised anchor still fails.
    Redirect JavaScript data and final destinations Retained, with generated-source, fallback-link, alternate site-prefix, and directory/flat URL checks.
    Superseded pages absent from nav/search Retained against rendered navigation and search output, including the duplicate research index.
    Manual/curriculum tests require every historic page and one exact menu order Retired in favor of rendered guide discovery, primary entry points, and evidence/design index reachability.
    Historical anchors require exact source headings Replaced by actual rendered anchor checks; explicit compatibility IDs may survive a heading rename.
    Curriculum freezes 27 example commands Execute every advertised command and reject duplicate example names; adding a working example no longer fails a count.
    Programming-model introduction repeats M10 closure prose Chronology stays checked in its milestone/implementation-plan owners; public routes and shipped declarations retain separate checks.
    README/homepage fixed cell count, parser fixed snippet count, exact setup sentence Keep canonical source equality, rendered cell order, required setup visibility, execution/output, and source-section validity; allow cell regrouping and wording changes.
    Historical notebook list comes from dispositions Discover actual retained notebook/chapter files and require evidence-index links; canonical notebook registries continue to protect bytes and outputs.
    SealQA notebooks require ordered menu entries and chapters require 220 lines Evidence-index discovery and byte-identity checks protect the notebooks; existing experimental-boundary and explanation checks protect chapter substance without a minimum length.
    Factual status, evidence, domain, and API checks Retained. They protect supported behavior and honest claims, not an arbitrary navigation arrangement.

    The pre-change focused baseline had 54 passing checks and four failures: the old Project menu name, mandatory historical menu entries, the 27-command count, and M10 closure prose in the programming-model introduction. Each obligation above has a named replacement; none is dismissed merely because it failed.
