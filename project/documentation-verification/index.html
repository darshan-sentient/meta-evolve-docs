    Verification procedure¶

    Install the locked documentation environment and run:

    uv sync --locked --group docs
uv run --locked --group docs mkdocs build --strict
uv run --locked --group docs pytest tests/test_documentation_routes.py tests/test_documentation_consolidation.py tests/test_docs_site.py
uv run --locked --group docs pytest tests/test_catalog_examples.py tests/test_research_references.py tests/test_research_catalog.py tests/test_applications_docs.py
uv run --locked --group docs pytest tests/test_context_evolution_notebooks.py tests/test_sealqa_notebooks.py tests/test_evidence_story.py

    The docs workflow installs the generated source package in a fresh environment and exercises exact downloadable bundles with that interpreter. Keep those checks separate from an editable checkout installation. Jupyter needs localhost sockets; the harness must be able to enforce its own OS confinement. A tool sandbox that blocks either is an environment restriction, not failed task quality.

    Paper-to-code review¶

    Method Source checked Mapping followed Finding
    Feedback Descent Algorithm 1 Two seed solves → comparison → one edit → exact measurement in feedback_descent.execute The lab omits iterative rationale history and preference acceptance; scripted records are not model outcomes
    ACE §3 Development lessons → revise → private search → neutral consolidation → held-out check Authored reflection and Greedy search are teaching reductions; outer persistence does not persist the whole study
    Meta-Harness Algorithm 1 Declared harness surfaces → governed diagnosis/source pull → development → private selection → held-out comparison Typed surfaces and bounded evidence access are narrower than program rewriting, history-filesystem access, and Pareto return in the paper
    GEPA transfer Algorithms 1–2 Prompt representation, user-owned reflection/grading, per-case metrics, explicit feedback, search Specialists is a component demonstration; tied frontier members, dominance removal, minibatch acceptance, and multi-module updates need their own implementation

    Transfer exercise result¶

    The review independently assigned prompt text to the artifact, task responses and traces to evidence, reflection to the proposer, and fixed case execution/grading to the evaluator. It identified distinct candidate selection, feedback selection, and work bounds. It then checked that a Specialists sketch cannot by itself implement GEPA's same-minibatch improvement gate or complete candidate-selection algorithm. Those gaps belong to #192 A6, not a new core abstraction in this change.

    The same review distinguished evolving a playbook's content from supplying observations, and filled in separate evaluator and budget roles for inner and outer loops. No additional model run is necessary to perform this exercise.

    Editorial findings¶

    • Source snippets come from canonical files. Complete supporting source is expandable; generated archives contain runtime files and required data/license material. Empty notebooks and live-looking fabricated captures were not added.
    • The Feedback Descent entry previously showed an undefined SDK factory as a runnable path. The replacement provides an explicit scripted rehearsal and states what a live integration must supply.
    • Research diagrams were checked for contained overflow. Source expansion, code copy, search, keyboard access, and light/dark layouts are part of final QA.
